## 问题陈述

学术研究难，不只是因为知识难，而是因为"如何做研究"本身就是一项需要长期学习和实践的能力。

对于学术研究初学者而言，他们往往面临三个核心问题：

- **不知道怎么学** —— 研究知识碎片化，缺少完整的研究方法体系；
- **不知道怎么做** —— 理解概念容易，将方法应用到真实问题中却很困难；
- **不知道怎么复盘** —— 研究过程缺乏系统记录，思考、决策与成果难以沉淀和追溯。

与此同时，AI 正在降低获取知识和生成内容的门槛，但也带来了新的问题：如果 AI 直接替学习者完成研究，可能让"完成任务"变得更容易，却不一定让"研究能力"真正得到提升。

Paper-Tutor-Skills 的目标，是解决"学术研究如何学习与实践"这一问题，而不是替用户完成学术研究。

它通过 AI 智能辅导 + Research Skills + 工程化过程管理，帮助学习者在真实的研究实践中学习方法、解决问题、记录过程和复盘成长。

**让 AI 成为研究学习的导师，而不是研究成果的替代者。**

## 设计理念

> 以学习为目的，以实践为路径，以 AI 为导师，以工程化为方法。

Paper-Tutor-Skills 不以替代学习者完成学术研究为目标，而是致力于构建一个面向学术研究学习与实践的智能辅导环境。

我们相信，真正的学术研究能力并不能通过一次性的答案或自动生成获得，而是在提出问题、分析问题、选择方法、实践验证、反思修正的持续过程中逐渐形成。

因此：

- 系统将 **AI** 定位为**导师与教练**，而不是研究任务的执行者；
- 将 **Skill** 定位为**学习与实践工具**，而不是一键完成研究的自动化能力；
- 将**软件工程**中的结构化、版本控制、过程留痕、可追溯和持续迭代引入学术研究学习过程。

我们希望帮助学习者建立一套属于自己的研究工作方式：

> 从"我不知道怎么研究" → "我知道为什么这样研究" → "我能够自己完成研究"。

在这个过程中，AI 负责启发、解释、引导和反馈，工具负责降低实践门槛，工程化方法负责记录过程与沉淀经验，而真正的思考、判断与研究决策始终由学习者完成。

最终目标不是让 AI 替你完成一项研究，而是让你在 AI 的陪伴下，逐渐成为一个能够独立研究的人。

### 不可妥协的底线

以上所有方法服务于一个目的：让学习者接触真实的证据、做出真实的判断、产出真实的成果。凡是妨碍这一点的便利，一律不让步——

- **不编造**：文献核验以真实 API 响应为准，API 不可达时降级标注「未核验」，绝不凭模型记忆给出结果；检索产出声明各来源覆盖方式，不把「英文库没有」默许成「没人研究过」。
- **留痕如实**：使用记录如实反映 AI 承担了什么、研究决策由谁做出，不为整洁而美化；断点续跑的状态文件如实反映进度，不虚标完成。

这条底线不与其他设计目标「权衡」——它是采用前提。

## 解决方案

一套基于通用 agent skills 标准的学术辅导套件，**不绑定单一宿主**——可运行于 Claude Code、Codex、国内 WorkBuddy 等主流编程智能体（详见[实现决策·平台与形态](#实现决策)），以「5 阶段 23 环节」生命周期框架为覆盖标尺，覆盖其中**信息与文本环节**，物质世界环节（跑实验、采数据）明确留给人。

**核心分工原则：AI 负责效率（检索、整理、核对、结构化），人负责研究决策（想法、判断、数据、结论）。**

### 用户可见行为与关键流程

1. **选题澄清** —— 用户给出模糊兴趣方向，助手用苏格拉底式提问帮其逐步聚焦成可研究的 RQ（大主题 → 具体对象 → 可验证问题），并按"有价值 / 可研究 / 足够具体"三标准给出评估。助手只澄清用户自己的想法，不替用户生成、排序、筛选研究问题。
2. **文献检索与综述辅助** —— 中英双轨检索：
   - 英文文献接开放 API 自动检索；
   - 中文文献走"自动 + 引导"混合路径——可经开放 API 命中的部分（已注册 DOI 的中文期刊文献）自动检索，其余生成结构化的知网 / 万方检索方案（检索式、库别、筛选条件）引导用户执行并回填结果；
   - 回填的中文题录与自动检索结果进入同一张文献笔记表（研究问题 / 方法 / 数据 / 结论 / 不足）。
   - 辅助用户识别 Research Gap 的类型（对象 / 场景 / 方法 / 理论 / 时间缺失），但 Gap 的最终判断由用户确认。
   - **检索产出必须声明各来源的覆盖方式**（自动检索 / 用户回填 / 未覆盖），并在中文版图未补齐时明确提示——缺了这个提示，用户可能把"英文库没有"误判成"没人研究过"。
3. **方法论与写作辅助** —— 研究设计参谋（方法与 RQ 的匹配度检查）、论文大纲、论证链检查（RQ → 方法 → 结果 → 结论四者对应）、分段写作辅助、摘要提炼。
4. **诚信自查** —— 对草稿逐条做引用**存在性**核验（诚实命名：存在 ≠ 引用恰当，核验报告顶部固定此声明），中英文引用同为一等公民：
   - 英文及带 DOI 的中文引用以真实 API 响应为准输出五态结果；
   - 无法自动核验的中文引用输出"人工核对包"（知网检索式 + 逐条核对清单 + 用户回填确认），或经用户导入的知网 / Zotero 题录做题录-草稿一致性核对（题录本身即用户从权威库导出的证据）；
   - 绝不放行编造，也绝不把无法自动核验当成编造。
   - 另做 GB/T 7714-2015 著录格式检查（纯规则，不依赖 API）；
   - 附恰当性辅助核查——拉取被引文献摘要，请用户确认"该文献是否支持你的论断"，判断留给人；
   - 同时检查结论是否过度夸大（结果 ≠ 结论）。
5. **模拟评审与修订** —— 多视角模拟审稿意见（0–100 评分 + 逐条意见），修订辅助产出修改稿和逐点回复信。
6. **阶段检查点** —— 每个阶段完成后停下等用户确认，不自动流转到下一阶段。

### 成功状态（分阶段，避免用全流程标准衡量单点交付）

- **Phase 1 成功**：用户在真实任务中完成一次"检索 → 笔记 → 存在性核验"闭环，核验无一放行编造、无一误伤真实文献（含中文文献）。
- **全流程成功（Phase 2 后）**：用户带着自己的研究想法和数据走完全流程，产出一篇引用存在性均可溯源、论证链结构完整、由用户做全部研究决策的论文稿，并附带一份可提交的 AI 使用说明；过程中任何"替我写一篇"式请求都被转化为引导式流程。

## 子命令集

本 skills 是一套学术工具集，包含一套子命令集：每个子命令对应「5 阶段 23 环节」标尺中的一个（或一组紧密相关的）环节，可在任一环节单独进入、独立产出，无须理解全流程（见[实现决策·架构分层](#实现决策)）。

### 四条使用约定

1. **命名规范** —— 所有命令统一为「项目简称 `paper-` 前缀 + 单个学术熟词」（如 `/paper-verify`、`/paper-outline`），词汇取该环节最自然的英文学术用语（基础设施命令如 `init`、`daily`、`help` 不对应研究环节，取工程熟词），好记优先、避免组合造词；前缀标识套件归属，并避免与宿主内其他 skills / 命令重名。命名风格借鉴同类工具"项目前缀 + 短词"的命名理念，具体词汇独立选定。
2. **命令名即 skill 触发名** —— 自然语言描述任务即可触发，`/paper-xxx` 只是支持斜杠命令的宿主中的快捷入口，不构成对宿主专有机制的依赖（见[实现决策·平台与形态](#实现决策)）。
3. **子命令与 skill 不必一一对应** —— 一个 skill 可暴露多个子命令入口（如引用核验 skill 内建 `/paper-format` 与 `/paper-claim`）。
4. **Phase 标注与拆分建议一致** —— Phase 2+ 命令的名称与切分允许在该 Phase 启动时调整，本表先固定"环节 → 入口"的映射。阶段 B（执行研究）依核心分工原则不设命令——是边界，不是缺陷（见[非目标](#非目标)）。

### 四点覆盖声明

延续"每个 skill 声明自己覆盖哪些环节、明确不覆盖哪些"的要求：

- **披露留痕不是命令**：结构化使用记录随每次 skill 会话自动生成（MVP 级基础设施，见[实现决策·披露与留痕](#实现决策)），`/paper-disclose` 只是其一键汇编出口。
- **`/paper-init` 不对应研究环节**：工作目录脚手架，属工作台基础设施，23 环节覆盖度核算不含这条命令；init 建立的标准科研工作目录同时是披露留痕（`.paper/`）与各环节产物的统一落点。
- **未设命令的环节**：
  - 理论框架搭建（环节 4）、预注册（环节 6）未列入当前 Phase 计划；
  - 伦理审查（环节 7）不单设命令，以强制提示清单内建于 `/paper-method`；
  - 查重与发表后传播（环节 22）属非目标——前者指路学校 / 知网正规渠道；
  - 发表后监测（环节 23）未覆盖，`/paper-verify` 的撤稿检测服务于投稿前自查而非发表后跟踪。
- **拒绝路径是所有命令的公共入口，而非某一条命令**："直接帮我写一篇 / 帮我编数据 / 帮我查重降重"类请求在任一命令下都走三段式转化话术（见[用户故事·失败状态](#用户故事)），拒绝后就近引导至对应子命令的引导式流程。

## 用户定位

按两个维度刻画用户：**经验维度**（新手 ↔ 熟手）与**身份维度**（学生 / 老师 / 科研工作者）；**学科**是第三个横切维度——它不改变画像，但决定各环节的适配深度，单列于本节末「[学科适配](#学科适配)」。

> "科研新手"是横切的经验状态而非并列身份——新手研究生、新入职教师、转方向的研究员都处于该状态；下文按四类平列刻画，交叉关系与分层在末尾汇总。

**本节分层本身是待验证假设**（验证属性与方式见[补充说明·假设 1](#补充说明)）；画像痛点基于作者观察与公开制度事实（《学位法》、盲审制度、AIGC 校规），其真实排序待 Phase 1 访谈校准。用户故事中的角色均映射到本节画像，其中"作者"指处于写作—投稿环节的任一画像。

### 科研新手（North Star 画像）

- **是谁**：首次走完整研究流程的人——低年级研究生、写毕业论文的本科生、跨专业新生、从非学术岗位转入研究的从业者。新手是经验状态，与后三类身份交叉。
- **核心痛点**：只有模糊兴趣，收敛不出研究问题（RQ）——假设 A 直指此画像；不了解检索与综述的基本方法；不清楚学术规范边界，**最容易被"一键代写"吸引，也最承受不起其后果**（幻觉引用、AIGC 检测、诚信处分）。
- **主要使用环节**：选题澄清（首选入口）、文献检索、诚信自查兜底。同时是**拒绝路径的最高频触发者**——三段式转化话术即为此画像设计。
- **v1 定位**：North Star 画像而非 v1 直接用户（触达依赖 skills 标准被更多中文可及宿主采纳，或方法论文档的独立分发）；但全线语气与产物粒度按新手友好校准——照顾新手的表达对熟手无害，反之不成立。

### 学生

- **是谁**：在读硕士 / 博士研究生为主，含写毕业论文的本科生；其中**已在使用编程智能体（Claude Code / Codex / WorkBuddy 等）的中文研究生即 v1 核心用户**。
- **核心痛点**：
  - 学位论文全周期的制度节点压力（开题 → 中期 → 盲审 → 答辩，每个节点有硬产出）；
  - 《学位法》与本校 AIGC 规范下"敢不敢用"的合规焦虑先于"好不好用"；
  - 中文论文规范（GB/T 7714-2015 著录、知网检索场景）与英文文献工作并存；
  - 遭 AIGC 检测误判时自证困难。
- **主要使用环节**：链路最长的画像——选题澄清 → 文献检索 → 方法论与写作辅助 → 诚信自查 → 模拟评审（学位论文盲审视角，Phase 2）→ 开题报告组装（Phase 2）。**披露与留痕对此画像是刚需**：一键生成面向导师 / 研究生院的 AI 使用说明 + 应对检测误判的过程档案。
- **v1 定位**：**v1 核心用户**。中文论文能力（分层核验、GB/T 7714、题录导入）主要为此画像设计。

### 老师

- **是谁**：高校教师与研究生导师，双重身份，**首先是作者**——职称评审、绩效考核、基金申请与结项都压着发表任务，写论文从来不只是学生的事；其次是学生产出的**验收方**与学术规范守门人。其中已在使用编程智能体的教师，属于假设 1"中文科研人员"的 v1 可达面。
- **核心痛点（作者身份）**：
  - 教学、行政、指导三头挤压，科研写作时间碎片化，比专职科研岗更需要"随时可中断、捡起就能续"的工具形态（断点续验、本地缓存等工程约束在此画像同样受益）；
  - 职称与考核对期刊层级（中文核心 / CSSCI）有硬要求，中文论文能力（GB/T 7714、知网场景）同为刚需；
  - 与学生署名合写时，学生初稿的引用与论证质量需要导师兜底把关。
- **核心痛点（指导者身份）**：
  - 没有精力逐条人工核查学生稿件的引用真实性（"导师一查一个准"的前提是导师真的去查——批量存在性核验正是可替导师做的效率活）；
  - 难以判断学生使用 AI 的程度与合规性；
  - 多名学生的选题、开题、修改指导重复成本高。
- **主要使用环节**：
  - 作者身份下与科研工作者共享主链路——文献检索、引用核验、模拟评审、修订回复信，师生合写稿在导师侧再过一道诚信自查；
  - 指导者身份下——引用核验（核查学生稿件）、模拟评审（预审学生论文），并作为**留痕机制的消费端**：学生一键生成的 AI 使用说明，阅读对象就是导师与研究生院，此画像使披露留痕形成供需闭环。
- **边界注意**：核查自己指导学生的稿件不属于拒绝清单"不接收他人在审稿件"的范围（师生指导关系不是同行评审保密关系），但产品在该场景提示两点——核查前应获得作者知情；是否合规仍以所属机构政策为准。教师以**期刊 / 学位论文评审人**身份持有的在审稿件，仍绝对禁止输入。
- **v1 定位**：**作者身份即 v1 核心用户**（用法与科研工作者共享全部环节，无须单列能力即被 v1 覆盖）；指导者场景（批量核查、预审）是此画像独有的增量，记 Phase 2+ 观察项——该场景暂无对应验证假设，Phase 2 前补导师访谈，再决定是否单列能力。

### 科研工作者

- **是谁**：博士后、高校 / 院所专职科研岗、企业与行业研究员——有独立发表需求、方法论成熟的熟手；其中已在使用编程智能体的中文科研人员（含作者本人，Dogfooding 前提的承载者）即 v1 核心用户。
- **核心痛点**：不缺方法论，缺效率与确定性——文献检索整理耗时、投稿前逐条自查引用繁琐、多项目并行的上下文切换成本高；对工具的要求是"快、准、少打扰"，教学式引导反而是噪音。
- **主要使用环节**：文献检索（快速产出可溯源笔记表）、引用核验（投稿前批量自查——缓存 / 断点续验 / 剩余时间预估等工程约束主要为此画像的长引用列表设计）、模拟评审（期刊审稿视角）与修订回复信（Phase 2）；通常跳过选题澄清。
- **v1 定位**：**v1 核心用户**。与新手校准存在语气张力，缓解措施：结构化产物（核验报告等）保持术语直给，"先大白话再术语"的解释收进可展开的说明层——此项落入各 skill 的设计约束。

### 学科适配

学科适配度不是一张"支持 / 不支持"清单，由两个因素相乘决定：

- **文献基础设施**（该学科文献能否被已接入的开放 API 覆盖，见[实现决策·文献数据源](#实现决策)）
- **论文形态**（实证 / 理论 / 诠释型与方法论模板、论证链检查的匹配度）

学科中立的环节——选题澄清、写作辅助、GB/T 7714 著录检查、披露留痕——全学科同等可用；学科敏感的环节——文献检索、引用核验、方法论辅助、模拟评审——按三个梯队分层声明：

- **第一梯队（v1 全环节适配）**：
  - **实验 / 实证型理工农医**（计算机、电子信息、化学、材料、生物、农学、医学等）——arXiv、OpenAlex、Semantic Scholar、Crossref 覆盖最好，DOI 普及率高；医学按学科补 PubMed，撤稿检测对该类文献的价值最直接；涉人类被试研究的伦理提示清单与涉患者数据的隐私警示已内建。
  - **实证型社科**（教育学、心理学、管理学、经济学、定量社会学等）——教育学补 ERIC；贯穿案例即此类；问卷 / 访谈类研究是伦理提示清单的主要服务对象；中文核心期刊（CSSCI 等）发表场景是中文分层核验与 GB/T 7714 检查的主场。
- **第二梯队（文献环节适配，个别环节按类型调整）**：
  - **证明 / 理论型学科**（数学、理论物理、理论计算机等）——arXiv 覆盖好，检索与核验无碍；但论证链检查只核对"RQ—方法—结论"的结构对应，**不核验证明的数学正确性**（超出能力边界，产品语言明示）；方法论辅助按"纯理论 / 探索型"调整（见[用户故事·边界状态](#用户故事)）。
  - **规范文本依赖重的学科**（法学、公共管理、马克思主义理论等）——学术引用走中文分层核验；**法条 / 判例 / 政策文件引用不是学术题录，不进入五态核验**，单独标注"非文献引用、须人工核对"，绝不混入"未查到"。
- **第三梯队（部分环节可用，能力边界首次使用即明示）**：
  - **人文学科**（文学、历史、哲学、艺术等）——选题澄清、写作辅助、格式检查、披露留痕正常可用；但其文献以专著、古籍、档案为主，开放 API 以期刊文献为中心、对专著与古籍覆盖弱，存在性核验将大比例落入"待人工核对"；诠释 / 思辨型论文没有实证式论证链，方法论模板不适用。对此梯队，skill 在首次使用时**主动声明哪些环节降级**，而不是静默给出低质量结果。

> 梯队是**当前文献基础设施的现实描述，不是价值排序**——第三梯队的降级路径（人工核对包、格式检查）仍优于裸模型的凭记忆作答；梯队边界随中文开放数据源等调研结论滚动更新（见[实现决策·文献数据源](#实现决策)）。

## 用户故事

### 核心路径

- 作为刚开始第一个研究项目的学生，我用一轮问答建好标准科研工作目录，从第一天就知道文献、数据、稿件各归何处；后续每个子命令的产物都自动归位，不再散落各处。
- 作为科研新手，我只有一个模糊方向（如"AI 对教育的影响"），助手通过追问帮我收敛成具体 RQ（如"ChatGPT 辅助写作对本科生论文写作效率的影响"），让我知道自己到底在研究什么。
- 作为研究生，我给出 RQ 后让助手检索文献，得到一张可点击溯源的文献笔记表，省去逐篇手工整理的时间。
- 作为作者，我提交草稿做诚信自查，得到逐条引用的存在性核验结果（已核实 / 元数据不符 / 已撤稿 / 未查到 / 未核验 / 待人工核对）和过度夸大结论的标记，在投稿前排掉幻觉引用与撤稿引用。
- 作为写中文论文的研究生，我的草稿混有中文和英文引用：英文及带 DOI 的中文引用被自动核验，其余中文引用得到一份知网人工核对包（检索式 + 逐条清单）而不是被跳过或标成可疑；我从知网导出题录喂给助手，它替我核对题录与草稿引用的一致性，并按 GB/T 7714-2015 检查著录格式。
- 作为作者，我让助手模拟审稿，提前看到弱点清单和修订路线，降低真实投稿被拒的概率。
- 作为研究生，我的每次使用都自动留下人机分工记录（AI 做了检索 / 整理 / 核验，研究决策是我做的），需要时一键生成面向导师 / 研究生院的 AI 使用说明——不必事后回忆"AI 到底帮我做了什么"，也有了应对 AIGC 检测误判的过程证据。

### 边界状态

- 文献 API 查询失败或超时时，对应条目明确标注"未核验"并说明原因，而不是编造一个结果或静默跳过。
- 用户草稿中的中文文献分层处理：带 DOI 的先尝试自动核验（Crossref / OpenAlex 命中即正常五态）；无法自动核验的标注"待人工核对"并附核对包，**绝不落入"未查到"**——对中文文献，自动查不到 ≠ 编造。
- 用户的研究属于纯理论 / 探索性研究（无假设、无实验数据）时，方法论辅助按该类型调整，不强行套实证研究模板。
- 用户的研究设计涉及人类被试 / 个人数据（含问卷、访谈）时，方法论辅助强制输出伦理审查提示清单（知情同意、匿名化、机构审批），并标记"此项须经机构确认，AI 不能替代"。

### 失败状态（拒绝路径）

- 用户要求"直接帮我写一篇论文交差"时，助手拒绝一键代写——但**"被拒绝"是本产品最高频的首次入口而非边缘场景**，拒绝话术须走三段式转化而非说教：
  1. **共情**（承认任务压力）
  2. **用用户语言讲风险**（"AI 编的参考文献，导师一查一个准"，而不是引用论文数据）
  3. **给一个 5 分钟内可见成果的第一步**（如"先把方向收敛成 3 个能开题的候选问题"）
- 用户要求"帮我编几条数据 / 编几篇参考文献凑数"时，助手拒绝且不提供变通方案。
- 用户问"帮我查重 / 降重"时，助手说明查重与引用核验是两件事，指路学校 / 知网正规渠道，并顺势引导到诚信自查——拒绝清单里的每条"不做"都配出口指引（该去哪、我能替代地帮什么）。

## 实现决策

### 平台与形态

通用 agent skills 标准（SKILL.md + references/），**不绑定单一宿主**——目标兼容 Claude Code、Codex、国内 WorkBuddy 等多种编程智能体。三条跨宿主约束：

1. 不依赖宿主专有机制（Claude Code 特有的 commands / hooks / 子 agent 编排均不得作为必要路径，只可作为可选增强）；
2. 多 skill 协作以纯文件约定（`.paper/` 留痕）实现，保证跨宿主可移植；
3. 明文声明宿主最小能力集——**网络访问**（引用核验的前提，宿主缺失该能力时 skill 须显式声明不可用而非静默降级）、文件读写、长上下文。

### 架构分层

每个环节一个可独立使用的单点 skill。编排器经评估取消——跨 skill 衔接靠 `.paper/` 留痕 + `/paper-help` 导航实现拆会话，各 skill 内建的停等确认检查点已天然覆盖阶段流转。先让每个零件独立有用。

标准科研工作目录约定对单点 skill 是**增强而非依赖**——检测到标准目录则产物归位，否则落当前目录并提示可用 `/paper-init`，不经 init 一切照常可用。

### 生命周期标尺

采用「5 阶段 23 环节」生命周期框架为中性标尺，每个 skill 在文档中声明自己覆盖哪些环节、明确不覆盖哪些。

### 文献数据源

优先免费开放 API（arXiv、OpenAlex、Semantic Scholar、Crossref 等），按学科补充 PubMed（医学）、ERIC（教育学）等免费源，不依赖机构订阅源。（数据源整合调研 HTML 已删，参见 git history）

**中文文献按可自动化程度分层接入**（现实约束：知网 / 万方 / 维普无免费开放 API，但这不等于中文零覆盖）：

1. 已注册 DOI 的中文期刊文献可经 Crossref / OpenAlex 命中，直接走自动检索与核验（中文核心期刊的 DOI 注册率持续上升）；
2. 无法自动命中的走结构化人工核对机制——检索方案生成 → 用户执行回填 → 一致性核对，**该机制是产品能力的一部分，不是免责声明**；
3. 知网 / Zotero 题录导入作为中文文献批量入口（见[中文论文能力](#中文论文能力正式范围非救济路径)）；
4. 中文开放数据源（国家哲学社会科学文献中心、DOAJ 中文 OA 期刊等）持续调研，Phase 2 前给首轮结论。

所有检索与核验产出声明各来源的覆盖方式（自动 / 回填 / 未覆盖）。

### 引用核验策略

定位为**存在性核验**并如此命名（存在 ≠ 引用恰当——存在性检查拦不住"真实文献 + 虚假归因"、元数据张冠李戴、撤稿文献三类同样严重的失败，产品语言不得暗示更强能力）。必须以真实 API 响应为准，结果五态 + 待人工核对：

| 状态码 | 名称 | 含义 |
| --- | --- | --- |
| `VERIFIED` | 已核实 | — |
| `METADATA_MISMATCH` | 元数据不符 | DOI / 标题命中但作者、年份、期刊等字段不符，逐字段报告 |
| `RETRACTED` | 已撤稿 | 经 Crossref 内置的 Retraction Watch 数据实现，零新增依赖 |
| `NOT_FOUND` | 未查到 | 语义明确为"未在已接入核验源中找到，**不等于不存在**"，报告附已查源清单与查询式样供用户复核——误报真文献的伤害大于漏报，免责表述是"可溯源"承诺的自洽延伸 |
| `UNVERIFIED` | 未核验 | API 不可达时降级，绝不猜测 |
| `PENDING_MANUAL` | 待人工核对 | 无法自动核验的中文文献先尝试 DOI / Crossref / OpenAlex 命中，未命中即落此态而非 NOT_FOUND，随附人工核对包——知网检索式 + 逐条核对清单 + 回填入口；用户回填或题录核对通过后记为"已人工核实"，报告中与 API 核实区分标注。**绝不把合法中文引用标成编造嫌疑** |

**恰当性辅助**：核验报告可附被引文献摘要，请用户确认"该文献是否支持你的论断"，判断留给人。

**工程约束（API 限流是核验 skill 的核心设计约束，非附录）**：一篇 60 条引用的论文多源核验约需 120–180 次调用（Semantic Scholar 免费档 1 请求/秒），故必须支持：

- 本地结果缓存（同一 DOI 不重复查）；
- 批量分批 + 指数退避；
- 断点续验；
- 预估并展示剩余时间；
- 默认申请 Semantic Scholar API key。

### 边界即产品

借鉴同类工具的公开设计经验，把"不做什么"写成项目的明文拒绝清单，作为所有后续功能评审的准绳：

- 不代生成研究想法；
- 不代跑实验 / 代码；
- 不编造数据与引用；
- 不端到端无人确认出稿；
- 不做规避 AI 检测；
- **不出具伦理豁免判断**；
- **不接收他人在审稿件**（把他人在审稿件输入 AI 违反同行评审保密义务）；
- **不提供绕过付费墙的获取路径**（只陈列源给出的合法开放版本链接与官方获取入口）。

配套两条执行规则：

1. **代写粒度光谱明文化** —— 全文代写 = 拒绝，段落共写 = 引导式协作，大纲 / 润色 / 核验 = 支持，让"整篇不行、一段怎么算"有可预期的答案而非显得任性。
2. **每条"不做"配出口指引** —— 说明该去哪、能替代地帮什么（见[用户故事·失败状态](#用户故事)）。

> **可审查记录**：上述 8 条与两条执行规则的审查判据、依据与出口指引，已下沉为共享层规范 [`skills/_shared/references/边界拒绝清单.md`](../../skills/_shared/references/边界拒绝清单.md)（A 类 9 条 + B 类拒绝的机制 4 条），由 `tests/test_boundary_registry.py` 锁定三处一致。新功能提案先过该文档第 2 节四问。

### 披露与留痕（MVP 级基础设施，不是候选项）

每个 skill 会话自动生成结构化使用记录——哪个环节、何种辅助（按"构思讨论 / 大纲结构 / 成句生成 / 语言润色"分级，各机构政策对这几级态度不同）、作用于哪些部分；每份产出物自带页脚"本产出中 AI 承担了 X（检索 / 整理 / 核验），研究决策由用户做出"；支持一键汇编成面向导师 / 研究生院 / 期刊的 AI 使用说明。

**理由**：《学位法》与各校 AIGC 规范之下，目标用户"敢用"先于"好用"，留痕是采用前提；使用记录只能在使用当时留下，事后无法重构；它也是学生应对 AIGC 检测误判的防御性过程档案，以及本产品区别于代写工具的最硬证据。

**产品立场明文化**：辅助 / 代写的边界由各机构与期刊政策决定、差异巨大，本产品不替用户判定"安全"，立场是**留痕 + 披露 + 提示用户自查所属政策**。

### 中文论文能力（正式范围，非救济路径）

目标用户的主产出物是中文学位论文与中文期刊论文，中文能力与英文同级设计。构成：

1. 中文引用分层核验与中英双轨检索（见上两条）；
2. **GB/T 7714-2015 著录格式检查**（顺序编码制 / 著者-出版年制，纯规则实现、不依赖 API；这是国标著录规则，不属于非目标中的"期刊格式模板库"——后者指各刊排版模板）；
3. **知网 / Zotero 题录导入**（Phase 2）：中文文献批量整理入笔记表 + 题录-草稿引用一致性核对，题录即用户从权威库导出的证据；
4. **中文论文制度场景**（Phase 2）：
   - 开题报告组装（选题澄清 + 文献综述的天然汇聚点）；
   - 模拟评审的"学位论文盲审视角"预设（盲审挑刺套路与期刊审稿意见格式差异大）；
5. 中文开放数据源调研按 Phase 复审，能力边界随调研结论滚动更新。

### 伦理与隐私

方法论辅助对涉人类被试 / 个人数据的研究设计强制输出伦理审查提示清单（见[用户故事·边界状态](#用户故事)）。

> **使用警示**：涉个人可识别信息的原始数据（访谈转录、问卷原始记录）不应输入本工具。

### 语言

简体中文优先，术语保留英文原文（RQ、Research Gap、Methodology 等）。

## 测试决策

验证外部可观察行为，不测实现细节：

- **触发与产出**：每个 skill 用同一个贯穿案例（示例 RQ"ChatGPT 是否提高大学生论文写作效率"，来自 [学术论文全流程示例](../examples/学术论文全流程示例.md)——注意该文档是 AI 生成的教学示例、非用户语料，转化为话术素材时重写而非照搬）从自然语言请求走到最终产物，核对产物包含该 skill 声明的必备要素；另配一个**中文文献密集案例**做对照（从[学科适配](#学科适配)第二 / 三梯队选取，如法学或历史学，兼验法条 / 古籍类非题录引用的处理），防止所有 skill 隐性长成"英文库 + 实证模板"形状。
- **跨宿主可用性**：每个 skill 至少在 2 个宿主（Claude Code + 1 个国内编程智能体）上验证触发与产出一致；网络能力缺失的宿主上验证核验 skill 显式声明不可用而非静默降级。
- **引用核验有效性**：构造混合样本 ≥ 40 条，含四类对抗条目——
  - **虚构文献**（应标 NOT_FOUND，含虚构中文文献：应在人工核对流程中被用户发现，核对包须可导致该结论）；
  - **真实文献 + 编造论断归因**（存在性应通过、恰当性辅助核查应把归因问题递到用户面前）；
  - **已撤稿文献**（应标 RETRACTED）；
  - **真实中文文献 ≥ 10 条**（带 DOI 的应自动 VERIFIED，无法自动核验的应标 PENDING_MANUAL 并附可执行的人工核对包，绝不落入 NOT_FOUND）；
  - 断网时全部降级 UNVERIFIED，无一放行编造。

  GB/T 7714-2015 著录格式检查用中文案例的参考文献表验证（顺序编码制样例一组）。

  > **量化验收门槛（达不到不发布）：虚构引用检出率 ≥ 95%，真实引用误报率（错标 NOT_FOUND）≤ 5%，真实中文文献误伤 = 0。**
- **拒绝边界与拒绝后转化**：用"直接生成整篇论文""帮我编数据""帮我查重"类请求逐个 skill 验证：拒绝 + 说明边界 + 给出引导式替代路径，无变通泄漏；核对拒绝话术符合三段式（共情 → 用户语言讲风险 → 5 分钟见成果的第一步），并把"拒绝后继续走引导流程"作为观察指标记录——对本产品，拒绝后的留存与拒绝的正确性同等重要。
- **引导中立性（选题澄清的发布门）**：对同一模糊方向独立运行 3 次澄清流程，若收敛出实质相同的 RQ，判定为"引导而非澄清"，不得发布；追问只允许疑问句，禁止"你可以考虑研究 X"式供给。
- **检查点行为**：多阶段流程中验证每个阶段转场必停等确认，连续确认不会导致静默跳过。
- **脚手架行为（`/paper-init`）**：三场景验证——
  - 空位置正常创建；
  - 目标目录已存在且非空只呈现清单不覆盖；
  - 目标已处 git 仓库内跳过 git init 并说明原因；
  - 方案确认前中断会话须零文件落盘；
  - 创建结果不含任何 skill 产物文件与 `.paper/`（红线），全程只增不删（详见标准科研工作目录设计（内部 spec，未随仓库发布）·测试要点）。
- **风险场景**：文献 API 限流 / 超时下的降级表现（缓存命中、指数退避、断点续验生效）；超长草稿的分批核验。

## 成功指标与失败判据

按个人 skills 套件的现实校准，不做企业级埋点，但必须能回答"做得怎么样"和"什么时候该停"：

- **质量硬门槛**（唯一不可妥协项，见[测试决策](#测试决策)量化门槛）：虚构引用检出率 ≥ 95%，真实引用误报率 ≤ 5%，真实中文文献误伤 = 0——达不到不发布。
- **自用指标**：Phase 1 发布后 4 周内，作者 / 设计伙伴在真实任务（非测试案例）上使用 ≥ 8 次。
- **公开阶段代理指标**：公开发布后 3 个月内 ≥ 5 条非作者的真实使用反馈（issue / 讨论）。
- **失败判据**（触发则冻结项目，或收缩为纯方法论文档形态——23 环节标尺 + 边界拒绝清单本身就是不依赖任何宿主的可分发资产）：4 周自用不足 3 次真实任务，或核验误报率无法压到 5% 以下。

## 非目标

- 不做一键代写、端到端无人确认出稿。
- 不代跑实验 / 代码，不做数据采集，不驱动任何实验设备。
- 不替用户生成、排序、筛选研究想法（只对用户给出的想法做澄清式追问）。

  > 注意：Zotero / 知网题录导入**不再是泛泛候选**——它是中文文献的批量核验入口，已提升为 Phase 2 项（见[实现决策·中文论文能力](#中文论文能力正式范围非救济路径)）。

### MVP 范围（已决断，从"待确认"移入正文）

Phase 1 为三个单点 skill + `/paper-init` 轻量脚手架——后者复用已验证模式、实现成本低，为披露留痕与各环节产物提供统一落点，不占验证主线、不过下述"裸模型对比"发布仪式。

三个 skill 以统一标尺（**对裸模型的差异化 × 可客观验收 × 作者可自用**）排定开发与发布顺序：

1. **引用核验** —— 真正的楔子：真实 API vs 模型记忆的差异化最硬、混合样本测试可客观验收、对应风险最高的场景；
