「裸模型 vs 带 skill」同任务并排对比，结果写进对应 skill 的 README——**增量讲不清就说明这个 skill 还没找到自己的价值**。这同时是营销素材，也是对抗"底层模型升级吞噬 skill 价值"的固定仪式。

> **v0.1.0 现状**：本对比**不是发布门的必要条件**（CLAUDE.md·发布门三条不含它），本目录三份记录的量化表均为待回填状态，按需补跑。本目录以「spec §X」「ADR·X」形式引用的设计文档为内部稿、不随仓库发布，故只留文字指代、不给链接。

## 方法约定

- **控制变量**：同宿主、同模型、同任务输入，唯一变量 = skill 有无；
- **任务来源**：优先取 [tests/fixtures/](../tests/fixtures/README.md) 的两个贯穿案例，保证对比任务与验收任务同源；
- **每 skill 一个子目录**（`evals/paper-<word>/`，随该 skill 的发布任务创建），内含：任务定义、裸模型侧完整记录、带 skill 侧完整记录、增量结论（一页说清"skill 到底加了什么"）；
- **结论落点**：增量结论摘要写进对应 skill 的 README；本目录保留完整记录供复核。

## 重跑时机

- skill 首次发布前（发布门）；
- 底层模型大版本更新后（记录 skill 价值是否被模型能力吞噬——这是产品的失败判据雷达，见 PRD·成功指标与失败判据）。

## 与 `/paper-init` 的关系

`/paper-init` 复用已验证模式、不占验证主线，**不过本仪式**（PRD·MVP 范围）；其发布门是「paper-init 与标准科研工作目录设计 spec·测试要点」（内部稿，未随仓库发布）的三场景与红线验证，验收记录见 [tests/paper-init/](../tests/paper-init/README.md)。
