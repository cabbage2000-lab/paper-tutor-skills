## 为什么不豁免这道门

paper-search 的价值不在「能列出文献」——裸模型也能列，且往往列得「看起来很全」。价值在于：**列的是真的、覆盖盲区被如实标注、研究判断留给用户**。这恰是裸模型最容易翻车之处，故必须并排对比、把增量讲清；讲不清不发布。

## 增量假设（待对比验证）

裸模型（无 skill）倾向：

- (a) **凭记忆列文献**，可能幻觉标题 / 编造 DOI；
- (b) **不声明覆盖方式**，把英文库结果当成研究全貌；
- (c) 顺嘴下「这个方向缺乏研究」的判断（越俎代庖，本应用户判断）；
- (d) 面对中文 RQ 时不给知网 / 万方检索方案，默认英文库 = 全部。

带 skill：真实 API 检索（不凭记忆）+ 强制覆盖方式声明 + 中文缺口提示 + Gap 判断交用户 + 生成知网 / 万方检索方案。

## 方法约定

控制变量：同宿主、同模型、同任务，唯一变量 = skill 有无。任务取 `tests/fixtures/` 两个贯穿案例：

- **主案例**（英文实证）：RQ「ChatGPT 是否提高大学生论文写作效率」；
- **中文密集案例**（法学 / 历史）：专验裸模型最易翻车处——中文轨凭记忆编造文献。

## 增量结论（待回填，一页说清）

一句话增量（待验证）：**裸模型给「看起来很全」的文献清单、替你判断空白、可能混入编造条目；带 skill 给可溯源的真实检索结果、如实标注覆盖盲区（尤其中文版图）、把研究空白判断留给你。** 中文密集案例是关键分水岭——裸模型在中文轨最易凭记忆编造。
