# 五入口路由约定

公开入口以 [`commands.yaml`](../commands.yaml) 为准，仅有 5 个。内部能力的状态、稳定 ID、对应入口与流程路径见 [`workflows.yaml`](../workflows.yaml)。两份清单各管一层，内部 ID 不再是需要用户记住的子命令。

## 根据意图进入流程

用户已说清要做什么时，选取对应流程并读取完整 `WORKFLOW.md`，承接已有材料和决定，从尚未完成的步骤继续。不要再展示内部能力全集、要求输入旧命令名，或让用户重复已给出的需求。只有需求会落到不同产物且无法从上下文判断时，问一个短问题，例如“你要核对题录与正文是否对应，还是要在线核验引用是否存在？”

用户只调用入口而没说任务时，询问想完成的产物，给最多三个贴近当前材料的示例，允许自由回答。用户明确要求完整命令表时，只展示 5 个公开入口。不把内部能力做成二级命令菜单，也不要求固定参数或英文模式名。

选错入口但意图明确时，说明一句对应的公开入口，读取该入口的 `SKILL.md` 并承接任务，不要求用户退出后重新敲命令。旧命令名作为自然语言意图线索可识别，但不注册旧别名；宿主不接受已移除的斜杠命令时，请用户在新入口后描述任务，不承诺旧快捷入口仍可调用。

## 加载与路径

内部流程与脚本留在原目录，以保持相对引用、Python 导入、CSL、模板等资源可用。`WORKFLOW.md` 不是技能入口，不应改回 `SKILL.md`。只有命中的流程及其要求的参考资料需要加载，禁止一次读入所有流程。

流程中的相对资源路径以该流程文件所在目录解析；执行脚本时先解析安装位置并使用脚本的绝对路径。工作目录仍是用户研究项目，输入输出路径相对项目解析，不能为了寻找脚本把产物写进技能安装目录。

流程需要另一能力时，按 `workflows.yaml` 的 `entry` 和 `request_zh` 生成“公开入口 + 自然语言任务”的交接语；不要向用户推荐内部 ID。`status` 非 `released` 的能力只说明尚未发布，不执行其流程。文献支撑补齐仍为开发中；可按用户意愿分别进行已发布的检索或写作辅导，不声称提供完整补齐能力。

## 单任务边界与兼容

合并的是入口，具体流程原有的研究边界、事实核验、稿件来源检查、确认点及输出契约继续有效。一次只处理用户要求的任务；跨能力的明确请求按依赖顺序完成，保留每个流程的检查点。不得因入口合并就自动跑完整研究流水线，或把“投稿”理解为授权在期刊系统提交。

`project.paper.yaml`、产物目录、脚本接口保持兼容。`.paper/` 标题继续写实际执行的内部能力 ID（例如 `paper-draft`），不改写成聚合入口 `paper-write`；旧记录不迁移、不重写。展示进度时把内部 ID 映射为中文任务与公开入口，同一入口内的多个能力记录不得误算为一个活动。

四层标注、学科适配、留痕及边界仍分别遵守[四层内容标注](四层内容标注.md)、[学科三梯队](学科三梯队.md)、[留痕契约](留痕契约.md)、[边界拒绝清单](边界拒绝清单.md)。
