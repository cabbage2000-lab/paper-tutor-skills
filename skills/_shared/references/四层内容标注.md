# 四层内容标注（共享权威定义）

| 项 | 内容 |
| --- | --- |
| 类型 | 共享约定权威定义（跨 skill 复用） |
| 范围 | 全部产物型 skill 的 HTML / MD 产物 |
| 上游 | PRD·披露与留痕 · [`报告组件库.md`](报告组件库.md) §1.2 四层语义色 / §3.1 标签族 |
| 校验 | [`tests/test_shared_conventions.py`](../../../tests/test_shared_conventions.py) |

产物里**每一句内容都要带来源标签**，读者一眼看出「这句话是谁说的」。这是「AI 负责效率、人负责研究决策」在产物层的落地——分工写在纸面上，不靠信任。

## 四层定义（符号是死线，不得改）

| 层 | 符号 | 语义 | 色值 | 含义 |
| --- | --- | --- | --- | --- |
| t1 | 👤 | 用户原话 | `#2b4a6f` 靛蓝（最重） | 用户自己说的、写的、拍板的内容，一字不改地引用 |
| t2 | 📋 | 常见事实 | `#7a6230` 赭石 | 该领域客观常见的选项 / 做法 / 规范，**摆事实不推荐**、不排序 |
| t3 | 🪞 | 系统归纳 | `#4a6b5c` 青灰 | AI 对以上材料的整理、归类、结构化——**可追溯回来源**，不含新判断 |
| t4 | ❓ | 待用户决定 | `#9a3b2e` 砖红 | 需要用户拍板的决策点，只许疑问句 |

**符号为什么是死线**：四层标注是 [`paper-disclose`](../../paper-disclose/SKILL.md) 汇编各产物、[`paper-help`](../../paper-help/SKILL.md) 全貌视图扫产物时识别内容来源的锚点。符号一漂移，跨产物对齐就断——同一 skill 的 SKILL.md 用一个符号、产物模板用另一个，产物会与其余 skill 的产物对不上。语义名的措辞可以有变体（如 t4 写「待用户决定」或「待用户验证」都行），**符号不行**。

## 没有第五层

**产物里不存在「AI 的新判断」层。**凡一句话既不是用户原话（t1）、又不是客观常见事实（t2）、又不能追溯回前两者的归纳（t3）、也不是交回用户的疑问（t4）——即判越界，不得写入产物。

这是「不下价值结论」底线的可自查形式：写产物时逐句问「这句归哪一层」，答不出就是越界。典型越界句式：「这个方向很有价值」「建议采用 X 方法」「这篇论文达到发表水平」「AI 辅助占比约 30%」。

## 用法

- **行内标签**：`<span class="tag-inline t1">👤</span>` + 内容，组件规格见 [`报告组件库.md`](报告组件库.md) §3.1。
- **图例区**：产物顶部固定四层图例（组件库 §2.3 `.legend`），并附一句「本报告不含『AI 的新判断』层」。
- **领域变体**：个别 skill 的语义名按场景微调是允许的，例如 `paper-review` 的 t2 是「模拟常见审稿维度（非推荐）」、`paper-figure` 的 t2 是「常见图类陈列」——**变的是语义名的措辞，符号与色值不变**。
- **另立色轴的特例**：`paper-disclose` 的读者标签轴用 `r1-r4`（导师 / 研究生院 / 期刊 / AIGC 检测），刻意避开 `l1-l4` 以防撞色，见组件库 §1.6。那是**另一个轴**，不是四层标注的变体。

## 不适用的场景

`paper-import` 用 `.st` 状态徽章族（✅ 有对应 / ⚠️ 差异 / 📋 未引）替代四层标注——它的产物是题录对应关系陈列，"来源"维度退化为"对应状态"维度，语义同源但不套用四层符号（组件库 §3.8）。
