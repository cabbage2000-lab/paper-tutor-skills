# `.paper/` 留痕契约（共享权威定义）

| 项 | 内容 |
| --- | --- |
| 类型 | 共享数据契约（生产者 / 消费者约定） |
| 生产者 | 全部产物型 skill（20 个，见下表；`paper-daily` 另有分歧形态，见文末「已知分歧」）——追加写入，不依赖任何专用写入器 |
| 消费者 | [`paper-disclose`](../../paper-disclose/SKILL.md)（按辅助级别汇编 AI 使用说明）· [`paper-help`](../../paper-help/SKILL.md) 全貌视图（扫留痕算阶段进度） |
| 上游 | PRD·披露与留痕（四级辅助级别） · CLAUDE.md 硬规则 5（`.paper/` 随 git 入库） |
| 校验 | [`tests/test_shared_conventions.py`](../../../tests/test_shared_conventions.py)（含与解析器的一致性锁） |

## 为什么需要契约

留痕有 **19 个生产者、2 个消费者**，字段一致此前全靠各 SKILL.md 里复制粘贴维持——没有定义、没有校验。任一 skill 把「AI 承担」写成「AI 负责」，`paper-disclose` 就静默漏读那一条，而没有任何机制会报错。留痕是用户应对 AIGC 检测误判的过程证据，**事后无法重构**，漏读的代价由用户承担。

## 落盘位置

项目根的 `.paper/` 目录，markdown 文件，**追加**写入（绝不覆盖、绝不重写历史条目）。目录在首个产物型命令首次使用时自动创建——`/paper-init` 明文不预建（预建空目录会让全新项目被误判成半成品）。

`.paper/` **随 git 入库，绝不写进 `.gitignore`**（CLAUDE.md 硬规则 5）。

## 条目格式

一次会话完成落盘后追加一条。标题行 + 字段列表：

```md
## 2026-07-21 14:30 · paper-abstract 摘要提炼

- 环节：阶段 C｜成文（环节 15，摘要）
- 辅助级别：成句生成（AI 从正文要点重组生成摘要句子、每句可追溯回正文、未添加正文没有的内容）
- AI 承担：正文要点提取、摘要句子重组生成、要素组织、产双产物
- 用户决定：摘要定稿、正文修订、关键词选择、目标场合字数调整
- 产物：manuscript/摘要.md
```

### 标题行

`## <YYYY-MM-DD[ HH:MM]> · paper-<命令名> <一句话描述>`

- 日期**必须是 `YYYY-MM-DD` 形态**（时间可选）——解析器按此正则取日期，写成「今天」「7月21日」会被整条跳过。
- 分隔符是 `·`（间隔号 U+00B7），不是 `-` 或 `|`。
- 命令名必须是 `paper-` 前缀的真实命令名（与 [`commands.yaml`](../commands.yaml) 的 `name` 一致）。

### 字段（前四项必填，`产物` 产物型必填）

| 字段 | 必填 | 含义 | 消费者依赖 |
| --- | --- | --- | --- |
| `环节` | 是 | 本次落在「5 阶段 23 环节」标尺的哪一环 | 全貌视图按阶段分组 |
| `辅助级别` | 是 | PRD 四级之一或多个（见下） | **disclose 按此分桶**，缺失则该条标「⚠️ 字段不全，原样陈列」 |
| `AI 承担` | 是 | AI 实际做了什么（如实，不美化） | disclose 陈列 |
| `用户决定` | 是 | 用户拍板了什么 | disclose 陈列 |
| `产物` | 产物型必填 | 落盘路径，**不含空白**（见下） | 全貌视图取产物路径 |

字段名后用全角冒号 `：` 或半角 `:` 均可解析；字段行以 `- ` 起始。

**skill 专属可选字段**：在上述字段之后自由追加（如 `摘要式`、`溯源`、`模式`、`覆盖声明`）。消费者忽略不认识的字段，不报错——扩展不需要改契约。

### `产物` 字段为什么必须不含空白

解析器（`paper-help` 的 `parse_trace_entries`）取 `product_path` 时**按空白切分**，只留第一段。所以写成 `manuscript/摘要.md（+ .html）` 会被截断成 `manuscript/摘要.md（+`——一个不存在的路径，而全貌视图照它去找产物就会判成「产物缺失」。

这不是假想：**本文档此前的示例自己就带着 `（+ .html）`**，15 个 skill 照抄，全部被截断（2026-07-29 用真实解析器实测发现并统一修正）。

正确写法：

| 情形 | 写法 |
| --- | --- |
| 单产物 | `- 产物：manuscript/摘要.md` |
| 主产物 + 渲染视图 | 只写主产物——`.html` 是 `.md` 的机械投影、同名同目录，不必进这个字段 |
| 多产物 | 顿号连、**中间不留空格**：`- 产物：literature/文献笔记表.md、literature/检索日志.md` |
| 二选一的产物名 | 尖括号占位内含选项：`- 产物：<落盘路径>/<图表诊断\|图表设计建议>.md` |
| 让路未产 | `- 产物：无（未产报告）`——括号内不留空格即可 |

守卫：[`tests/test_shared_conventions.py`](../../../tests/test_shared_conventions.py) 扫全部 SKILL.md 的 `产物` 字段，含空白即失败。

## 四级辅助级别（PRD 披露分级）

| 级别 | 含义 | 披露分量 | 当前使用它的命令 |
| --- | --- | --- | --- |
| **构思讨论** | AI 引导、整理、陈列，未替用户判断、未成句 | 最轻 | topic / search / screen / method / logic / import / verify / review / disclose / submit / typeset |
| **大纲结构** | AI 搭结构骨架，用户填内容与取舍 | 中 | outline / proposal |
| **成句生成** | AI 生成了进入产物的句子 | 重 | draft / abstract / revise / plot（plot 标「重」） |
| **语言润色** | AI 改写用户已写的句子 | 中 | draft（与成句生成并存时都写） |

一条留痕可含多级（如 `辅助级别：构思讨论 + 成句生成`）。**disclose 按级分桶、不按命令分桶**——因为一个命令可能跨多级。

## 命令 → 留痕级别对照

| 命令 | 留痕级别 |
| --- | --- |
| `paper-topic` / `paper-search` / `paper-screen` / `paper-method` / `paper-logic` / `paper-import` / `paper-verify`（含 `format` / `claim`）/ `paper-review` / `paper-disclose` / `paper-submit` / `paper-typeset` | 构思讨论 |
| `paper-outline` / `paper-proposal` | 大纲结构 |
| `paper-draft` | 成句生成（+ 语言润色） |
| `paper-abstract` / `paper-revise` | 成句生成 |
| `paper-plot` | 成句生成（重） |
| `paper-figure` | 混合级（B 诊断与 C a/c/d/e 构思讨论；C b 大纲结构；C f 交 `paper-plot`） |
| `paper-style` | 混合级（默认构思讨论；用户明确要示例改法、AI 给出改写句时该次 + 语言润色） |
| `paper-anchor` | 混合级（默认构思讨论；用户明确要改法示例、AI 给出改写句时该次 + 语言润色） |
| `paper-init` / `paper-help` / `paper-doctor` | **不写留痕**（工作台基础设施，不占 23 环节） |

新增产物型 skill 时在此表加一行，**不要**在自己的 SKILL.md 里列举同辈命令——那会让每加一个 skill 都要改 N 处。

## 已知分歧（待决，勿当作范例照抄）

`paper-daily` 的留痕落 `daily/.paper/YYYY-MM-DD.json`，是**JSON 格式的日报输入参数记录**（RQ / 时间窗 / 检索参数 / 抢发命中 / 覆盖声明），不是本契约的 markdown 条目形态。后果：**两个消费者当前都读不到 daily 的留痕**——disclose 汇编不到它，全貌视图算进度时看不见它。

这是有原因的（daily 是 infra 命令、产物目录独立、留痕内容偏参数而非人机分工），但目前是隐性分歧。两条出路，需要一次设计决策：① daily 另补一条 markdown 条目到项目根 `.paper/`；② 契约扩展为「markdown 条目 + JSON 侧车」双形态、两个消费者都支持。**在决策前，新 skill 一律按上文的 markdown 条目格式写。**

## 三条底线

1. **不编留痕** —— 只记实际发生的会话，绝不凭模型记忆补全未发生的记录。
2. **不抹痕迹** —— 用户可要求隐去某条，但产物顶部强制覆盖声明「按用户选择隐去 N 条」；绝不彻底删除。
3. **不下结论** —— 留痕只记事实，禁「AI 占比 X%」「AI 辅助程度高 / 低」这类价值判断（判断归读者，见 [`四层内容标注.md`](四层内容标注.md)「没有第五层」）。
