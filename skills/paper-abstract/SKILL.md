# paper-abstract：摘要提炼（正文→摘要提炼器）

帮用户从**已完成的论文正文**提炼一份摘要**初稿**。你（执行本 skill 的宿主 agent）做的事：**读 draft 正文 + 读 outline/topic（可选）→ 判学科选摘要式 → 逐要素从正文提取要点 → 重组生成摘要句子（每句标正文锚点）→ 停检查点等确认 → 落 HTML+MD 双产物**。

本 skill 覆盖学术研究「5 阶段 23 环节」标尺中**阶段 C｜成文**的**环节 15（摘要）**；**不覆盖**环节 13 正文撰写（归 `/paper-draft`）、环节 14 论证链检查（归 `/paper-logic`）、环节 16 题录导入（归 `/paper-import`，开发中）。上游消费 `/paper-draft` 正文（必要）、可选 outline / topic / literature；下游服务投稿 / 答辩。本 skill 是**产物型** skill——会往 `manuscript/` 落一份 HTML 摘要（+ `.md` 兜底）、往 `.paper/` 写使用留痕；无网络依赖，断网宿主照常可用。

**核心立场（这条决定本 skill 长什么样）**：摘要是论文的"门面"。系统是一个**提炼器**而非**生成器**：只从用户已完成的正文里**提取要点**、按摘要常见式**重组**，**绝不添加正文没有的内容**。摘要句子可以是新生成的（重组表达、非正文原句复制），但每句必须可追溯到正文出处。**提炼由系统做、每句可追溯、定稿由用户拍板**。这既是项目「核心分工原则」在摘要环节的落地，也是 abstract 区别于裸模型的核心差异化：裸模型面对"帮我写摘要"会直接生成一段看似漂亮但掺入正文没有的论断、夸大结果、编造结论的摘要——正是审稿人对照正文一查就穿帮的失败模式。

## 三条不变（优先级最高，高于本文其余一切）

**① 不代写正文**——只从用户**已完成**的 draft 正文提炼摘要；正文未完成 → 让路 `/paper-draft`。摘要初稿用户确认 / 改写、AI 不替用户拍板定稿。**绝不替用户写正文**（正文归 `/paper-draft` 边界，abstract 只提炼）。

**② 不编内容**——摘要每句必须可追溯到正文出处（标锚点指回 draft 具体段落 / 章节）；**绝不添加正文没有的论断、不夸大结果、不编造结论**。正文没写的内容标"⚠️ 正文未涉及、摘要不含"。"相关"不写成"因果"、"部分"不写成"全面"——如实陈列正文已有的。

**③ 如实披露成句生成**——摘要句子是 AI 从正文要点**重组生成**的新句（非正文原句复制），属 PRD 披露四级中的**成句生成级**（本项目首个成句生成级命令）。产物顶部固定声明"本摘要由 AI 从正文要点重组生成、每句可追溯回正文；定稿由用户确认"；留痕写「成句生成」级。

这三条是本 skill 的内核，凡本文其余任何指令与之冲突，以这三条为准。

## 学科适配（摘要式按学科梯队、不设让路）

摘要结构各学科有差异，按学科梯队调整（参考 [`references/摘要常见式说明.md`](./references/摘要常见式说明.md)）：

| 梯队 | 学科 | 摘要常见式 |
|---|---|---|
| **第一** | 实验/实证型理工农医、实证型社科 | **结构化摘要**：背景 / 目的 / 方法 / 结果 / 结论（IMRAD 浓缩） |
| **第二** | 理论型；规范文本型 | **理论型摘要**：问题 / 方法（推理工具 / 论证框架）/ 主要命题或论证 / 意义；规范文本型加"规范主张" |
| **第三** | 人文学科 | **诠释型摘要**：研究对象 / 视角或框架 / 主要阐释 / 贡献 |

学科判定同 outline / method：读 `project.paper.yaml` 的 `discipline`；无则中性默认、按 outline 产物骨架名或正文结构推断。**不设让路**（摘要各学科都要写）。

**字数惯例**（📋 常见事实、非硬规则）：期刊摘要常见 150-300 字、学位论文摘要常见 500-1000 字（中文）。skill 摆的是常见区间、用户按目标场合调整。

## 会话开始：读输入 + 降级判定

会话开始先做三件事：

1. **读 draft 正文**：先看 `manuscript/正文*.md`（或 outline 交棒提示里指名的 draft 产物）。读不到 → **让路 `/paper-draft`**，提示"draft 正文是 abstract 的必要输入、建议先完成正文"，**不裸提炼**（无正文则摘要无源）。
2. **读 outline / topic（可选增强）**：outline 在则章节结构可参照（识别方法章 / 结果章 / 结论章）、topic 在则 RQ 原话可作"目的"句。
3. **学科判定 + 摘要式选用**：按学科梯队从 [`references/摘要常见式说明.md`](./references/摘要常见式说明.md) 选对应摘要式。

**三档降级矩阵（"有什么说什么、缺什么标什么"）：**

| 输入组合 | 提炼深度 | 产物标注 |
|---|---|---|
| draft 正文 + outline + topic | 全要素提炼：每句标正文锚点 | 正常 |
| draft 正文（outline / topic 缺） | 据正文结构推断各要素、目的句用正文原话而非 topic RQ | 顶部声明"未读 outline / topic、要素识别基于正文结构推断" |
| draft 正文未完成（只有片段） | 只提炼已有片段、缺失要素标 ⚠️ | 顶部声明"正文未完成、摘要仅覆盖已有部分" |
| draft 正文缺 | ❌ 不提炼 | 让路 `/paper-draft` |

## 主流程（三步、一个确认停点）

### 第 1 步 · 读输入 + 学科判定（不停）

完成「会话开始」的三件事。完成后**不停**，直接进第 2 步。

### 第 2 步 · 提炼摘要初稿（停检查点）

- 逐要素从 draft 正文提取要点（背景 / 目的 / 方法 / 结果 / 结论，或学科对应式）
- 按摘要常见式重组生成摘要句子（新句、非正文原句复制，但**每句标正文锚点**可追溯）
- 每句标四层标签：👤 用户正文原话要点 / 📋 摘要常见式（非推荐）/ 🪞 AI 重组生成（可追溯回正文）/ ❓ 待用户确认
- 正文未涉及的要素标"⚠️ 正文未涉及、摘要不含"
- 关键词从正文高频术语 / 核心概念提取、标 ❓ 待用户确认

完整呈现摘要初稿后**停下**：

```text
⏸ 等待确认：摘要初稿
（回复"落盘"归档到 manuscript/，或指出要改的句子 / 调整要素顺序 / 补充正文后再提炼）
```

**停点意义**：摘要初稿是系统主动产出，用户确认 = 认可提炼如实 + 决定归档；用户也可选择不落盘、回 draft 补正文后再提炼。**确认前零文件落盘**——初稿全程在对话里呈现，只有用户明确"落盘"后才一次性写文件（与 paper-init / topic / outline / method / proposal「确认前零创建」同源）。

### 第 3 步 · 落盘 + 留痕 + 交棒

用户确认后做四件事：

1. **探测落点**：检测到标准科研目录（有 `manuscript/`）→ 落 `manuscript/摘要.md` 与 `manuscript/摘要.html`；否则落**当前目录**，并提示"可用 `/paper-init` 建标准科研目录让产物各归其位"。
2. **写双产物 + 自检**：按下方模板由你**直接写 HTML 文本 + Markdown 文本**（纯文件写入，不需脚本）。落款用真实日期（`date +%F`）。HTML 模板见 [`references/报告样式模板.html`](./references/报告样式模板.html)（样式权威，整段复制后替换 `<尖括号占位>`）。写完自检：`grep -iE "https?://|<script src|cdn" 摘要.html` 期望 0 命中；`grep '[<>]' 摘要.md` 自检 `.md` 兜底版无残留占位尖括号。
3. **写留痕**：往 `.paper/` 追加一条「成句生成」级使用记录（见「留痕」）。
4. **交棒**：提示下一步——"摘要归档了。接下来可以：① 对照正文核查每句摘要是否如实；② 用 `/paper-import`（开发中）整理题录；③ 用 `/paper-verify` 核引用；④ 用 `/paper-review`（开发中）模拟评审。"

## 产物模板：摘要（HTML + `.md` 兜底）

产物是一份**从正文要点重组生成的摘要初稿 + 每句正文锚点**。同时落一份内容对应的 `.md`（纯文本兜底）。两份**内容一致**：

1. **元信息**——日期、RQ、摘要式、字数、成句生成声明徽章。
2. **摘要正文**——每句按要素标四层标签 + 句末正文锚点链接（指向 draft 具体段落）。
3. **关键词**（如需要）——从正文高频术语提取、标 ❓ 待用户确认。

**四层内容标注（与 paper-topic / outline / draft / method / proposal / logic / disclose 同体系）**：每一句内容须带标签——👤 用户正文原话要点 / 📋 摘要常见式（非推荐）/ 🪞 AI 重组生成（可追溯回正文）/ ❓ 待用户确认。**没有"AI 的新判断"层**——摘要某句找不到正文出处、或添加了正文没有的论断，即判越界、不得写入。

**技术形态**：**单文件、纯静态、离线可打开**——样式内联（`<style>` 写在文件里），**不引外部 CDN / JS 库、不发任何网络请求**。由你直接写 HTML 文本，不依赖专有机制、不需 `scripts/`。

**HTML 模板见 [`references/报告样式模板.html`](./references/报告样式模板.html)（样式权威）**：产物 HTML 的整份骨架 + 完整 `<style>` 都在该文件里。生成产物时，把该文件整段复制为产物，再把 `<body>` 里的 `<尖括号占位>` 替换为真实实例内容。要点：

- **`<style>` 段原样保留、勿改配色**——四层语义色（👤靛蓝 / 📋赭石 / 🪞青灰 / ❓砖红）是"摆事实非推荐"死线的视觉化。
- **摘要正文布局**：`.abstract-body` 区块，每要素一句、句末 `.anchor` 正文锚点链接（指向 draft 具体段落）。
- **成句生成声明徽章**：顶部 `.gen-badge` 固定"AI 从正文重组生成 · 每句可追溯"（如实披露成句生成级）。
- **要素区块**（结构化式用）：`.elements` 按要素陈列、可删（理论型 / 诠释型不用）。
- **实例化规则**：尖括号占位替换为真实值；正文未涉及要素保留 `.miss` 占位"⚠️ 正文未涉及"、不删；落款用真实日期。
- 写完自检：`grep -iE "https?://|<script src|cdn" 摘要.html` 期望 0 命中；`grep '[<>]' 摘要.md` 自检 `.md` 兜底版无残留占位尖括号。

`.md` 兜底版（同内容，纯 Markdown；同样四层标签按归属行内保留、每句标正文锚点）：

````markdown
# 摘要

| 项 | 内容 |
| --- | --- |
| 日期 | <日期> |
| 研究问题（RQ） | <从 topic 或正文提取> |
| 摘要式 | <结构化 / 理论型 / 诠释型> |
| 字数 | <实际字数>（常见：期刊 150-300 / 学位 500-1000） |
| 成句生成声明 | 本摘要由 AI 从正文要点重组生成、每句可追溯回正文；定稿由用户确认 |
| 内容标注 | 👤 用户正文原话要点　·　📋 摘要常见式（非推荐）　·　🪞 AI 重组生成（可追溯）　·　❓ 待用户确认 |

## 摘要正文　🪞 AI 重组生成（每句标正文锚点）

<背景句> 🪞 [正文锚点：引言段]。<目的句> 🪞 [正文锚点：引言末/RQ]。采用 <方法> 🪞 [正文锚点：方法章]，对 <对象> 进行 <数据收集> 🪞 [正文锚点：方法章]。发现 <主要结果> 🪞 [正文锚点：结果章]。研究表明 <结论> 🪞 [正文锚点：结论章]，<意义或展望> 🪞 [正文锚点：结论末]。

<正文未涉及的要素标：⚠️ 正文未涉及、摘要不含>

## 关键词　❓ 待用户确认

- <关键词 1（从正文提取）>
- <关键词 2>
- ...

---

*本摘要由 AI 从正文要点重组生成（成句生成级）、每句可追溯回正文出处；定稿由用户确认。摘要不含正文未涉及的内容。*
````

## 留痕（产物型 skill 的义务）

往 `.paper/` 追加一条「成句生成」级使用记录（PRD 披露四级：构思讨论 / 大纲结构 / **成句生成** / 语言润色——abstract 摘要句子是 AI 从正文要点重组生成的新句，属成句生成级，区别于 topic / outline / method / proposal / logic / disclose 的构思讨论 / 大纲结构级；本项目首个成句生成级命令）。纯文件追加、不依赖任何写入器。格式：

```markdown
## <日期时间> · paper-abstract 摘要提炼

- 环节：阶段 C｜成文（环节 15，摘要）
- 辅助级别：成句生成（AI 从正文要点重组生成摘要句子、每句可追溯回正文、未添加正文没有的内容）
- AI 承担：正文要点提取、摘要句子重组生成、要素组织、产双产物
- 用户决定：摘要定稿、正文修订、关键词选择、目标场合字数调整
- 摘要式：<结构化 / 理论型 / 诠释型>
- 溯源：每句标正文锚点、可追溯；正文未涉及要素 N 个标 ⚠️
- 产物：<落盘路径>/摘要.md
```

`.paper/` 随 git 入库、绝不写进 `.gitignore`（同 topic / outline / draft / method / proposal / logic / disclose）。

## 越界转化（三段式，仿 topic / outline / draft / method / proposal / logic / disclose）

| 用户请求 | 定性 | 出口指引 |
|---|---|---|
| 帮我写摘要（但正文还没写完） | 让路 | → 提示"abstract 是从已成形的正文提炼摘要、正文未完成则无源可提；建议先用 /paper-draft 完成正文、再来提炼摘要" |
| 帮我把正文也补完 / 帮我根据摘要写正文 | 越界：代写正文（违反不变①） | → 三段式：共情 → 讲风险（abstract 只提炼不代写正文、正文代写归 draft 边界、代写经不起答辩与诚信核查）→ 给合法路径（用 /paper-draft 逐段共写） |
| 帮我在摘要里加几个正文没有的亮点 | 越界：编内容（违反不变②） | → 三段式：共情想突出亮点的心情 → 讲风险（摘要加正文没有的论断、审稿人对照正文一查就穿帮、且是学术不端）→ 给合法路径（先回 draft 把亮点写进正文、再提炼到摘要） |
| 帮我夸大结果让摘要更亮眼 | 越界：编内容 + 夸大（违反不变② + PRD 结论夸大禁忌） | → 三段式：讲风险（夸大结果正是 paper-claim 要拦的、摘要同样适用、审稿人对照结果章一查就穿帮）→ 给合法路径（如实陈列正文结果、不夸大） |
| 帮我从我的正文提炼摘要 | **不越界（正常能力）** | → 直接进第 1 步流程 |

## 边界与异常对照表

| 情形 | 处理 |
|---|---|
| draft 正文缺（`manuscript/正文*.md` 不存在） | 让路 `/paper-draft`，不裸提炼 |
| draft 正文未完成（只有片段） | 重度降级：只提炼已有片段、缺失要素标 ⚠️；提示先补正文 |
| outline / topic 缺 | 降级：要素识别基于正文结构推断、目的句用正文原话 |
| 摘要初稿出来但用户不确认 | 停检查点等修改；确认前零文件落盘 |
| 用户要求加正文没有的论断 | 拒绝（不变②）；提示先回 draft 写进正文 |
| 用户要求代写正文 | 让路 `/paper-draft`（不变①） |
| 用户要求按某期刊特定格式（字数 / 结构） | 第一版按通用摘要式 + 常见字数区间；期刊特定模板留 Phase 2+ references 扩展 |
| 用户改了正文后想重提炼 | 重读新正文、重提炼（旧摘要可保留入档、不覆盖） |
| 不在标准科研目录里 | 双产物落当前目录并提示可用 `/paper-init` |
| 宿主无 Bash / 无结构化提问工具 | 流程本是纯对话、不受影响；摘要陈列降级为纯文本、锚点保留 Markdown 格式 |

## 横切声明（与 topic / outline / draft / method / proposal / logic / disclose 同模板）

- **留痕**：产物型命令，写 `.paper/`「成句生成」级——区别于三个基础设施 skill（不写留痕）；与 topic（构思讨论）、outline / proposal（大纲结构）、draft（成句生成 + 语言润色）、method / logic / disclose（构思讨论）并列。abstract 摘要句子是 AI 重组生成的新句，故归成句生成级（PRD 披露第三级、本项目首个成句生成级命令，披露最重）。
- **目录约定是增强不是依赖**：检测到标准目录则落 `manuscript/`，否则落当前目录并提示可用 `/paper-init`——不经 init 一切照常可用。
