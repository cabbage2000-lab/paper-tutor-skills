# 论断检索式规则

| 项 | 内容 |
| --- | --- |
| 类型 | 转换规范（论断 → 检索式 → 真实 API 调用） |
| 服务对象 | `paper-anchor` 主流程第 2 步（生成检索式）与第 3 步（取候选） |
| 上游 | [`论断类型库.md`](./论断类型库.md) 的分类结果 |
| 检索层 | `../../paper-search/scripts/search.py`（复用，本命令不新写数据源层） |
| 死线 | 三条不变② —— 候选一律来自真实 API 响应，找不到就说找不到 |

**与 `paper-search` 的拆解不是一回事，勿套用。** search 的输入是 RQ——一个**待回答
的问题**，拆法是 PICO 概念块（对象 / 干预 / 结果 / 场景），目的是把某方向的研究版图
铺开。本命令的输入是**已成立的命题**，要拆的是它的**可检验部分**，目的是找到能对该
命题作证的具体研究。同一句话在两处的拆法不同：

| 输入 | search（RQ） | anchor（论断） |
| --- | --- | --- |
| 「AI 工具能否提高大学生写作效率？」 | 拆 PICO → 铺版图 | — |
| 「近年来大学生使用 AI 工具日益普遍。」 | — | 剥「日益普遍」→ 查该现象的实证报道 |

## 0. 通用禁令

1. **禁凭记忆列文献**——检索式生成后必须真调 `search.py`。你脑子里的那几篇看起来很
   合适的文献，一半的 DOI 是编的。
2. **禁把检索式当结论**——检索式是给用户改的草案，第 2 步必须停下让他改。
3. **禁替用户挑**——结果按客观键排序（默认年份降序），不排相关度、不给 Top-N、不说
   「这几篇最合适」。

## 一、四条转换规则

### 规则 1 · 剥掉程度副词与价值词

它们表达的是**论断的强度**，不是它的内容，进了检索式只会让召回变差。

| 该剥掉的 | 例 |
| --- | --- |
| 程度 / 趋势副词 | 日益、逐渐、越来越、显著、极大、普遍、广泛 |
| 价值词 | 重要、必要、亟需、不容忽视、有意义、关键 |
| 主观限定 | 众所周知、不难看出、显然 |

> 论断：「近年来大学生在论文写作中**日益普遍**地使用 AI 工具。」
> 检索式：`college students AI tools academic writing use`（「日益普遍」不进）

**剥的时候要记账**：被剥掉的强度词正是第 3 步「改弱表述」出口要回来处理的东西——
检索结果只能支撑到某个强度，而原句的强度是多少，得靠这笔账对比。

### 规则 2 · 提取可检索实体

留下能在文献库里匹配到的成分：

| 实体类 | 例 |
| --- | --- |
| 研究对象 | 大学生 / 研究生 / 中学教师 / 上市公司 |
| 场景 / 领域 | 论文写作 / 课堂教学 / 供应链 / 门诊 |
| 变量与构念 | 写作效率 / 学习动机 / 全要素生产率 |
| 具名对象 | 量表名（TAM、SCL-90）、理论名、方法名、算法名 |
| 时空范围 | 中国 / 长三角 / 2020 年后（后者用 `--year-from` 而非塞进查询串） |

**筛选条件走参数、不塞查询串**：年份用 `--year-from` / `--year-to`，类型用 `--type`。
把「2022年以后」写进 query 只会污染词袋匹配。

### 规则 3 · 按论断类型选策略

三个策略对应类型库的前四类；第⑤类（价值判断）**不检索**。

| 策略 | 用于 | 怎么组 | 例 |
| --- | --- | --- | --- |
| **a · 实证现象** | ① 事实陈述 | 对象 + 场景 + 现象词，可加 `prevalence` / `survey` / `trend` | `college students generative AI use survey` |
| **b · 原始出处追溯** | ② 方法依据 ③ 理论框架 | 方法 / 理论的**准确原名**（含英文原名）+ `original` / `development` / `validation`；量表加 `scale validation` | `technology acceptance model Davis original` · `SCL-90 scale validation Chinese` |
| **c · 同方向同类研究** | ④ 对比创新 ③ 的应用先例 | 对象 + 变量关系，配 `--year-from`（近 N 年），**不加**「first」「novel」这类词 | `AI writing tool effect writing quality higher education` |

**策略 b 的两个坑**（真实跑出来的，勿踩）：

1. **别加 `--year-from`，且默认排序会害你**——原始出处按定义是**老文献**（SCL-90 是
   1970 年代、TAM 是 1989 年），而 `search.py` 默认 `--sort year_desc`，会把它们排到最
   末；配上 `--limit 10` 就一条都看不到。实测拿 `SCL-90 symptom checklist validation`
   检索，前排全是 2026 年的应用研究，**没有一条是原始出处**。策略 b 须：不设年份下限、
   调大 `--limit`、并优先看 `--sort source_count`（被多个库同时收录的更可能是那篇经典）。
   若前排仍全是新近应用研究，**如实说「未检索到原始出处」**，转类型库 ② 的「确认来源
   性质」出口——不要拿一篇 2026 年的应用研究充当量表出处。
2. **中译名要先还原成英文原名**——方法与理论的中译常有多个（「计划行为理论」／「计划
   行动理论」），检索前先定英文原名（Theory of Planned Behavior）。中译名检索不到不等
   于该理论不存在，这是类型库 ③「核对术语」出口的技术原因。

### 规则 4 · 中英双轨与覆盖声明

继承 `paper-search` 的红线 2，且在本命令**更要紧**：导师说「缺文献支撑」时想要的
常常正是中文文献（尤其教育学、管理学、法学、马理论）。

- **英文轨**：`search.py` 自动检索（Crossref / OpenAlex / Semantic Scholar / arXiv，
  按学科可加 PubMed / ERIC）。
- **中文轨**：`search.py` 的 `cnki` 源 `coverage` 恒为「需用户回填」——**它不自动检索**。
  须按 `paper-search/references/知网万方检索方案模板.md` 生成字段限定布尔式给用户去
  粘贴，回填的题录并入同一张 `literature/文献笔记表.md`。
- **未纳入中文库自动检索时，必出这句原文**：

> 英文库没检索到 ≠ 没人研究过。中文文献需要你到知网 / 万方按上面的检索式自行检索，
> 本次结果不代表研究全貌。

## 二、`search.py` 调用口径

```bash
python3 ../paper-search/scripts/search.py \
    --query "college students AI writing tools academic writing" \
    --year-from 2022 --limit 10 \
    [--year-to 2026] [--type journal-article] \
    [--sources crossref,openalex,semantic_scholar,arxiv,eric] \
    [--per-source 20] [--sort year_desc|source_count] [--no-cache]
```

**接口若变更需同步本文档**（同 `paper-daily` 的已知观察项——两个命令都复用这个脚本，
它改了这里不改就会静默失效）。

输出 JSON 的四个关键字段：

| 字段 | 用途 |
| --- | --- |
| `network_status` | `ok` / `degraded`（部分源不可达或降级但有结果）/ `offline`（走降级路径） |
| `coverage[]` | 逐源的 `coverage`（自动检索 / 需用户回填 / 未覆盖）、`hit_count`、`outcome`。**产物的覆盖声明照抄它，不自己编** |
| `results[]` | 候选题录（title / year / doi / authors / venue…）。摆进产物的必须是这里的真实条目 |
| `stats` | `raw_hits` / `after_dedup` / `shown` / `cache_hit_rate`。产物里写「共 X 条去重后 Y 条」照它写 |

`degraded` 不等于失败：某个源降级、其余源有结果时仍是可用结果，**但覆盖声明须如实
写出哪个源降级了**，不得笼统写「已检索四个数据源」。

## 三、零命中与降级的处置

| 情形 | 处置 |
| --- | --- |
| 有结果 | 摆候选 + 五字段比对 + ❓；并列摆「改弱表述」出口（不变③，**有候选也要摆**） |
| **零命中** | 如实写「未检索到可支撑该论断的文献」，**把改弱 / 删除出口前置**；可提议换检索式再试一轮（换同义词、放宽年份），但不得靠反复换词硬凑出一篇 |
| `network_status: offline` | 产「缺口清单 + 分类 + 支撑要求 + 检索式」，**不产候选**；顶部显式声明「检索不可用、候选未获取」，交用户日后自行检索 |
| 某源 `degraded` | 照常出结果，覆盖声明里逐源写明 |
| 中文轨未覆盖 | 必出规则 4 的原文提示 |

**零命中不是本命令的失败，是一个有信息量的结果**：它意味着这句话目前没有文献能撑，
用户要么继续找（换库、换词、问导师），要么把话说轻一点。这两条路都比挂一篇似是而非
的文献强。
