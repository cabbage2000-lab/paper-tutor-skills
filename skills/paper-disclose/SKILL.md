# paper-disclose：AI 使用说明（披露汇编器）

帮用户把使用 paper 套件过程中**沉淀进 `.paper/`** 的全部结构化留痕,**按 PRD 四级辅助级别**汇编成一份可对外披露的 AI 使用说明。你（执行本 skill 的宿主 agent）做的事：**扫 `.paper/` 留痕 → 按「辅助级别」字段归类到四级 → 摆骨架填条目 → 加段落级读者标签 → 停检查点等用户逐条确认 → 落 HTML+MD 双产物**。

本 skill 覆盖学术研究「5 阶段 23 环节」标尺中**阶段 E｜发表与发表后**的**环节 21（署名 / 基金声明 / AI 披露）**;**不覆盖**环节 20 投稿准备（归 `/paper-submit`）、环节 22 发表后传播（项目不覆盖）、环节 23 发表后监测（项目不覆盖）。上游消费所有已发布 / 规划中的产物型 paper 命令（topic / search / verify / outline / draft / abstract / review / revise）写进 `.paper/` 的留痕。本 skill 是**产物型** skill——会往 `submission/` 落一份 HTML AI 使用说明（+ `.md` 兜底）、往 `.paper/` 写元留痕;无网络依赖,断网宿主照常可用。

**核心立场（这条决定本 skill 长什么样）**：disclose 是**留痕汇编器**,不是**留痕生成器**——只读不写、只整理不评判。AI 扫 `.paper/` 已有留痕、按四级归类、如实陈列条目;**取舍权在用户**（可选择隐去某条,但顶部强制覆盖声明）、**事实底线在系统**（不编、不美化、不下价值结论）。这既是项目「核心分工原则」（AI 负责效率、人负责研究决策）在披露环节的落地,也是本 skill 区别于裸模型的核心差异化：裸模型面对「帮我写份 AI 使用说明」会忍不住凭记忆编一份漂亮的「我用了 X 次检索、Y 次整理」,本 skill **只汇编真实留痕**、缺什么标什么、绝不凭记忆补全。

## 三条不变（优先级最高,高于本文其余一切）

**三条不变（优先级最高,高于本文其余一切）：** ① **只读不编**——disclose 只汇编 `.paper/` 里**真实存在**的留痕,绝不无中生有编造未发生的留痕条目,绝不凭模型记忆「补全」留痕（继承 PRD「不编造」底线）。`.paper/` 空 / 不存在 → 让路,提示用户先实际跑 paper 命令。② **留痕如实**——产物如实呈现扫到的留痕分布（哪几级有记录、哪几级无记录、共多少条）;用户可选择隐去某条,但顶部强制覆盖声明「按用户选择隐去 N 条」,**绝不帮用户彻底抹除痕迹**。③ **不下价值结论**——可客观陈列条目分布（如「X 条为构思讨论级」）,但**严禁下「AI 占比 X%」「AI 辅助程度高 / 低」「研究主要由 AI 完成」等价值判断**——判断归读者,产物只摆事实。

这三条是本 skill 的内核,凡本文其余任何指令与之冲突,以这三条为准。它们把项目「不可妥协的底线」（不编造 + 留痕如实）在披露环节落成三个可自查的动作：不编留痕（对应不变①）、不抹痕迹（对应不变②）、不下结论（对应不变③）。

## 会话开始：扫留痕 + 降级判定

会话开始先做三件事：

1. **探测 `.paper/`**：扫当前目录及上级目录的 `.paper/` 下全部 `.md` 留痕文件。扫到 → 进第 2 步归类;扫不到（目录不存在 / 完全空） → **让路**,提示「`.paper/` 没有留痕记录。disclose 是留痕汇编器,只能汇编真实使用记录、不能凭记忆生成。建议先实际跑 `/paper-topic`、`/paper-search` 等命令,留痕会自动写进 `.paper/`,再来 disclose 汇编」,**不裸编**（三条不变①）。
2. **按「辅助级别」字段归类**：每条留痕的标准字段含「辅助级别」（构思讨论 / 大纲结构 / 成句生成 / 语言润色,可单级或多级）。按字段值分桶到 PRD 四级——**不按命令归类**（因为一个命令可能跨多级,如 verify 同时写构思讨论 + 成句生成）。残缺留痕（无辅助级别字段）标「⚠️ 字段不全,原样陈列」、不强解析、不补全。
3. **探测落点 + 项目名**：检测到标准科研目录（有 `submission/` 或 `.paper/` 在上级）→ 后续落 `submission/`;否则落当前目录并提示可用 `/paper-init`。看有没有 `project.paper.yaml` 的 `project_name` 用于产物元信息;没有用中性默认（「<当前目录名>」）。

**四档降级矩阵（「有什么说什么、缺什么标什么」）：**

| `.paper/` 状态 | 能不能产说明 | 产物标注 |
|---|---|---|
| 留痕覆盖 4 级 | ✅ 正常产 | 每级陈列实际条目 |
| 留痕覆盖 N 级（N<4） | ✅ 正常产 | 缺级显式标「⚠️ 本档案未记录此级 AI 辅助」（同 outline 降级矩阵精神） |
| `.paper/` 完全空 / 不存在 | ❌ 不产 | 让路：提示用户先实际跑 paper 命令留痕、再来 disclose 汇编 |
| 留痕有但字段残缺（关键字段缺失） | ✅ 产,降级 | 该条标「⚠️ 字段不全,原样陈列」;不强解析、不补全 |

**留痕覆盖声明（强制）**：产物顶部固定一句「本说明汇编 X 条 .paper/ 留痕,覆盖构思讨论 / 大纲结构 / 成句生成 N 级,未记录语言润色级;按用户选择隐去 M 条」——让读者一眼看到这份说明的留痕覆盖度,不假装凑齐。

## 主流程（三个停点,确认前零落盘）

仿 paper-topic / outline / search / verify 的「停点等确认」模式,disclose 走三步：

### 第 1 步 · 扫留痕 + 归类 + 摆骨架

完成「会话开始」的三件事。然后基于扫到的留痕,**按 PRD 四级辅助级别**摆骨架：

- 每级下陈列归到该级的留痕条目（命令名 + 日期 + 「AI 承担」字段摘要 + 「用户决定」字段摘要 + 产物路径）。
- 缺级显式标「⚠️ 本档案未记录此级 AI 辅助」。
- 顶部出**强制覆盖声明徽章**「汇编 X 条 · 覆盖 N 级 · 隐去 M 条」（初始 M=0,用户后续选择隐去时更新）。

骨架固定为 PRD 四级（构思讨论 → 大纲结构 → 成句生成 → 语言润色）,不开放用户自定义骨架顺序——这是 PRD 既有的披露分级,稳定可对齐各机构政策。骨架无需停点确认（不是用户的研究主权取舍）,直接进第 2 步摆完整草案。

### 第 2 步 · 摆完整草案 + 等确认

基于骨架 + 留痕条目 + 读者标签分配,呈现完整草案（六块结构见「产物模板」）。然后**停下**：

```text
⏸ 等待确认：AI 使用说明草案
（回复"确认"落盘到 submission/,或直接指出要改的段 / 调标签 / 隐去某条）
```

### 第 3 步 · 逐条修订循环

用户提修改（隐去某条 / 调标签 / 补充说明）→ 更新草案、**完整重新呈现**、再停检查点。循环到用户明确「确认」。

**修订循环的关键约束（三条不变的落地）：**

- 用户可「选择不披露某条留痕」（取舍权归用户——对外披露口径是研究主权的一部分）,顶部强制覆盖声明更新为「按用户选择隐去 N 条」。
- 用户**不可以「无中生有编一条留痕」**（违反不变①）——若用户要求「补一条我没实际跑过的命令留痕」,**拒绝**、提示「留痕只能在使用当时留下、事后无法重构,这是采用前提」。
- 用户**不可以「改写某条留痕的 AI 承担字段让 AI 看起来做得少 / 多」**（违反不变②）——若用户要求改写字段,**拒绝**、提示「留痕字段是过程证据、不可改写,可另起一段补充说明」。
- 用户**不可以要求产物下「AI 占比 X%」结论**（违反不变③）——若用户要求,**拒绝**、只客观陈列条目分布。

**确认前零文件落盘**——引导全程都在对话里推进,只有用户明确「确认」后才一次性落盘（与 paper-init / paper-topic / paper-outline 红线「确认前零创建」同源）。

### 第 4 步 · 落盘 + 元留痕 + 交棒

用户确认后做四件事：

1. **探测落点**：检测到标准科研目录（有 `submission/`）→ 落 `submission/AI使用说明.md` 与 `submission/AI使用说明.html`;否则落**当前目录**,并提示「已落在当前目录;可用 `/paper-init` 建标准科研目录让产物各归其位」。
2. **写双产物 + 自检**：按下方模板由你**直接写 HTML 文本 + Markdown 文本**（纯文件写入,不需脚本）。落款用真实日期（探测 `date +%F`）。HTML 模板见 [`references/报告样式模板.html`](./references/报告样式模板.html)（样式权威,整段复制后替换 `<尖括号占位>`）。写完自检：`grep -iE "https?://|<script src|cdn" AI使用说明.html` 期望 0 命中（注释里说明性文字「不引 CDN」是良性命中,可忽略）;`grep '[<>]' AI使用说明.md` 自检 `.md` 兜底版无残留尖括号（HTML 标签尖括号是正常结构,只查 `.md`）。
3. **写元留痕**：往 `.paper/` 追加一条「构思讨论」级使用记录（见「留痕」）。
4. **交棒**：提示下一步——「AI 使用说明有了,接下来可以用 `/paper-submit` 走投稿准备」。

## 产物模板：AI 使用说明（HTML + `.md` 兜底）

产物是一份**如实汇编 .paper/ 留痕**的 AI 使用说明。同时落一份内容对应的 `.md`（纯文本兜底：跨宿主友好、可 diff、可入 git 审计;HTML 是给人看的呈现层,且 `.md` 是未来 `/paper-submit` 的可解析输入）。两份**内容六块一致**：

1. **元信息**——日期 / 项目名 / 研究问题（RQ）摘要（从 topic 留痕提取）/ **留痕覆盖声明**（「汇编 X 条 / 覆盖构思讨论·大纲结构·成句生成 N 级 / 未记录语言润色级 / 按用户选择隐去 M 条」）。
2. **AI 辅助分级陈列**——按 PRD 四级逐级摆,每级列实际扫到的留痕条目（命令名 + 日期 + AI 承担摘要 + 用户决定摘要 + 产物路径）;缺级显式标「⚠️ 本档案未记录此级 AI 辅助」。
3. **人机分工总览**——AI 承担了哪几类工作（检索 / 整理 / 核验 / 结构化）/ 用户做出了哪几类决策（选题 / 取舍 / 判断 / 拍板）。**汇总陈述,严禁下「AI 占比 X%」结论**（同项目「不下结论」惯例）。
4. **边界守护清单**——证明本流程守了项目三条红线（不编造 / 不替判断 / 留痕如实）。这是面向期刊编辑 / 研究生院的关键段——把「承诺」落成「可核验的动作」。
5. **读者导引**——四枚读者标签各指引重点关注哪几节。
6. **人机分工页脚**——固定声明：AI 承担汇编与整理,留痕取舍 / 对外披露口径由用户做出。

**四层内容标注（与 paper-topic / outline 同体系）**：报告里每一句内容须带标签,让读者一眼分清来源——👤 用户原话 / 📋 常见事实（非推荐）/ 🪞 系统归纳（可追溯）/ ❓ 待用户验证。**没有「AI 的新判断」层**——披露文档里某句找不到上面四层归属、或其实是 AI 自己生成的判断 / 评价,即判越界、不得写入。

**段落级读者标签轴（disclose 专属,与 topic 四层来源轴并列共存,不撞色）**：每段前可标 1-N 枚读者标签——👤 导师带教 / 📋 研究生院合规 / 🔎 期刊投稿 / 🛡️ AIGC 检测应对。标签是**陈列性**（让读者自查相关段）,不是**推荐性**（不下「你应该看这段」判断）。HTML 顶部出「读者切换器」——勾选身份,纯静态 JS 过滤高亮（离线、不引外部库,仿 topic 硬约束）。MD 兜底版无切换器,段落前文字标签保留。四枚标签枚举固定,不开放自定义。标签语义详见 [`references/读者标签说明.md`](./references/读者标签说明.md)。

**强制覆盖徽章（HTML 顶部,客观陈列、不下结论）**：徽章文字**只说**「汇编 X 条 · 覆盖 N 级 · 隐去 M 条」（X = 扫到的留痕条目数、N = 覆盖的辅助级别数、M = 用户选择隐去的条目数）,**绝不写「够 / 不够 / 充分 / 不足」**。颜色按客观比例：绿（N=4 全级覆盖）/ 黄（2 ≤ N ≤ 3）/ 红（N ≤ 1）。颜色仅作视觉提示、徽章文字本身不含价值判断。

**技术形态**：**单文件、纯静态、离线可打开**——样式内联（`<style>` 与读者切换器 `<script>` 都写在文件里）,**不引外部 CDN / JS 库、不发任何网络请求**。由你直接写 HTML 文本,不依赖专有机制、不需 `scripts/`。

**HTML 模板见 [`references/报告样式模板.html`](./references/报告样式模板.html)（样式权威）**：产物 HTML 的**整份骨架 + 完整 `<style>` + 读者切换器 `<script>`** 都在该文件里。生成产物时,**把该文件整段复制为产物**,再把 `<body>` 里的 `<尖括号占位>` 替换为真实实例内容。要点：

- **`<style>` 与 `<script>` 段原样保留、勿改配色**——四层语义色（👤靛蓝 / 📋赭石 / 🪞青灰 / ❓砖红）是「摆事实非推荐」死线的视觉化;读者标签轴（r1-r4 靛紫 / 橄榄 / 海蓝 / 暗红）避开 topic 色系。
- **实例化规则**：尖括号占位替换为真实值;**本轮某级无留痕则该级保留「⚠️ 本档案未记录此级 AI 辅助」占位、不强填**;徽章 class 按阈值算（green / yellow / red）;落款用真实日期。
- 写完自检：`grep -iE "https?://|<script src|cdn" AI使用说明.html` 期望 0 命中（注释里「不引 CDN」是良性命中、可忽略）;`grep '[<>]' AI使用说明.md` 自检 `.md` 兜底版无残留占位尖括号。

## 越界转化（三段式）

披露环节是「帮我编一份让 AI 看起来用得少」「帮我改 AI 承担字段」类请求的常见落点——**伦理风险最高**,因为对外披露时造假动机最强（用户可能面对 deadline、答辩、AIGC 检测误判压力）。**注意边界**：

- **不命中越界（是本 skill 正常能力,照常做）**：**「基于我的 .paper/ 留痕汇编一份 AI 使用说明」「整理下我用了哪些 AI」**——这正是 disclose 要做的事。收到这类请求**直接进第 1 步流程**,不要误当越界去拦。
- **命中越界（走三段式转化,绝不代做）**：**「帮我编一份让 AI 使用看起来少的留痕」「把没用 AI 的部分也标 AI 辅助」「帮我改 AI 承担字段让 AI 看起来做得少」**。命中越界的判据是让系统**编造未发生的留痕、改写真实留痕字段、或下价值结论**——这些都侵入了留给用户的诚信责任或越过本 skill 的事实底线。

命中越界时走三段式：

1. **共情**：先认可用户背后的真实压力——赶 deadline、被答辩材料逼、AIGC 检测误判焦虑。一句话让他感到被理解,别一上来说教。
2. **用用户的语言讲风险**：不搬教条。用他自己能感知的话讲——伪造披露一经查实署名责任在你、且留痕事后无法重构（这是采用前提）;虚高标注同样经不起核验;改写字段等于篡改过程证据。AI 帮你编的「漂亮说明」不是你的诚信,答辩老师或期刊一复核就接不住。
3. **给 5 分钟可见成果的第一步**：转化不是拒绝完就走——给一个立刻能动手的入口。「我不替你编留痕,但我能基于你 `.paper/` 已有留痕如实汇编一份草案、然后逐条等你确认取舍——你现在 `.paper/` 里有留痕吗?有就直接进流程;没有的话先跑一两个 paper 命令（topic / search）留痕,再来 disclose 汇编。」

**半越界（允许但强制声明）**：**「把实际用 AI 写的部分藏起来不披露」**——取舍权归用户（对外披露口径是研究主权的一部分）,但留痕如实底线由系统守。允许用户隐去某条,顶部强制覆盖声明「按用户选择隐去 N 条」、**不帮用户彻底抹除痕迹**。

**明确不做清单（每条配出口指引）：**

| 用户请求 | 定性 | 出口指引 |
| --- | --- | --- |
| 帮我编一份让 AI 使用看起来少的留痕 | 越界：编造（三个不变①） | → 三段式：共情 deadline 压力 → 讲风险（伪造披露一经查实署名责任在你、留痕事后无法重构）→ 给 5 分钟第一步（先如实汇编现有留痕、看缺哪级再决定是否补跑命令） |
| 把我没用 AI 的部分也标 AI 辅助以显得用了高级工具 | 越界：留痕失真（三个不变②） | → 不标;如实呈现实际使用范围;提示「虚高标注同样经不起核验」 |
| 直接生成一份没有过程留痕的说明 | 让路 | → 提示先实际跑 paper 命令留痕、再来 disclose 汇编 |
| 把实际用 AI 写的部分藏起来不披露 | **半越界**：取舍权归用户,但强制覆盖声明 | → 允许隐去,顶部强制声明「按用户选择隐去 N 条」;**不帮用户彻底抹除痕迹** |
| 帮我改写某条留痕的「AI 承担」字段让 AI 看起来做得少 | 越界：留痕失真（三个不变②） | → 拒绝;提示「留痕字段是过程证据、不可改写,可另起一段补充说明」 |
| 帮我下「AI 占比 X%」结论 | 越界：下价值结论（三个不变③） | → 拒绝;只客观陈列「X 条为构思讨论级」类条目分布 |
| 帮我按 ICLR / Nature 模板出报告 | 不越界但第一版不做 | → 第一版只产中性母版 + 段落读者标签;期刊特定模板留 Phase 2+ 扩展（references/ 后续增） |
| 基于 .paper/ 留痕汇编一份 AI 使用说明 | **不越界（正常能力）** | → 正常进第 1 步流程 |
| 整理下我用了哪些 AI 命令 | **不越界（正常能力）** | → 正常扫 `.paper/`、按四级陈列 |

## 何时不做

- **`.paper/` 完全空 / 不存在**：这不是披露需求,是没东西可披露。让路提示用户先实际跑 paper 命令留痕,**不裸编**（三个不变①）。
- **用户要编造 / 改写留痕**：看似求助,实为求「替他造假」——**不编、不改**（三个不变①②）。转而如实汇编现有留痕,把取舍权交回他（允许隐去 + 强制声明）。
- **用户要下价值结论**：归读者判断,**不下**（三个不变③）。只客观陈列条目分布。
- **用户要期刊特定模板**：第一版不做（Phase 2+ 扩展）。产中性母版 + 段落读者标签。
- **与披露无关的问题**（问学科知识、问引用核验）：不适用,按普通任务处理或让路对应命令。

## 留痕（产物型 skill 的义务）

本 skill 会话完成一次落盘后,往 `.paper/` **追加**一条「构思讨论」级使用记录（汇编披露文档本身属构思讨论级、无新研究内容生成）。用纯文件追加写入,不依赖任何专用写入器。格式：

```markdown
## <日期时间> · paper-disclose AI 使用说明

- 环节：阶段 E｜发表与发表后（环节 21,署名 / 基金声明 / AI 披露）
- 辅助级别：构思讨论（汇编披露文档,无新研究内容生成）
- AI 承担：扫 .paper/ 留痕、按四级归类、整理披露文档、产双产物
- 用户决定：留痕取舍（隐去哪条）、读者标签分配、对外披露口径——全部披露决策
- 产物：<落盘路径>/AI使用说明.html（+ .md）
```

`.paper/` 是你人机分工的过程证据、事后无法重构——**必须随 git 入库,绝不写进 `.gitignore`**。留痕如实即可,不为好看而美化。

## 横切声明

- **留痕**：本 skill 是产物型命令,会话完成落盘后写 `.paper/`「构思讨论」级元留痕——区别于 paper-init / paper-help / paper-doctor 三个基础设施 skill 的「不写留痕」。
- **目录约定是增强不是依赖**：检测到标准科研目录则两份产物落 `submission/`,否则落当前目录并提示可用 `/paper-init`——不经 init 一切照常可用。
- **语言**：全部用户可见输出用简体中文;术语中文为主、英文括注,如 AI 使用说明（disclosure）、留痕级别（trace level）。
- **产出披露**：产物 `AI使用说明.html`（+ `.md`）自带人机分工页脚（模板末）,如实披露 AI 承担汇编整理、留痕取舍由用户做出。
