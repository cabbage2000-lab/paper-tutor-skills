# 纳排标准与排除理由码（paper-screen references）

> **陈列性、非推荐性**——本文档陈列 PICO / PICoS / SPIDER 三套学界常见的纳入排除标准要素、排除理由码表，以及筛选台账（`literature/筛选台账.md`）的字段定义。**选用哪个框架、每条标准的具体内容、每一篇文献最终纳入还是排除，都由你逐条拍板**——本文档只陈列常见要素，不推荐框架，不替你判定纳排。
>
> 本文档同时是 [`skills/paper-screen/scripts/screen.py`](../scripts/screen.py) 解析筛选台账时**取值的唯一权威**，但四列的把关强度并不一致。「去重 / 标摘筛 / 全文筛」三列必须与下文精确一致（逐字匹配，含标点），写成同义词（如把「保留」写成「已保留」、把「进入全文」写成「进入全文评估」）会让脚本无法把该行归入任何一类，进而判定「守恒等式」不平或误报「筛选未完成」。**这三列是有意的设计：宁可报错，也不可把一条记录静默地归错档。**「排除理由码」列则不同：脚本只检查该列在「全文筛 = 排除」时是否**非空**，不校验取值是否属于「三、排除理由码表」——填入任意非标准文本不会触发守恒不平、也不会报错，退出码仍是 0，唯一后果是该文本会在排除理由分布里单独成一个统计桶，让流程图的排除理由明细失真，需要你自己核对是否用了码表规定的字符串。

## 一、筛选台账字段定义（唯一权威）

`literature/筛选台账.md` 是一张 8 列 markdown 表格，列序固定如下（`screen.py` 按位置解析、不认表头文字，但强烈建议表头就写这 8 个字段名，方便你自己核对）：

`序号 | 题录锚点 | 来源库 | 去重 | 标摘筛 | 全文筛 | 排除理由码 | 备注`

> 再次提醒：下表「允许取值」列出的每一个字符串都必须逐字照填。这些字符串是 `screen.py` 里写死的比对目标，不是措辞建议——同义词、近义表达都不会被识别。

| 字段名 | 含义 | 允许取值 | 是否必填 |
| --- | --- | --- | --- |
| 序号 | 该行在**本台账内**的顺序号，正整数；`screen.py` 靠"首列是否纯数字"识别数据行，非数字或列数不足 8 的行会被直接跳过、不计入任何统计 | 正整数（1, 2, 3…），同一台账内应唯一 | 必填 |
| 题录锚点 | 指向 `literature/文献笔记表.md` 中该条文献的 `#` 列值，把筛选台账的行与真实文献笔记对应起来 | 文献笔记表中真实存在的 `#` 值；不得填写笔记表未收录的编号 | 必填 |
| 来源库 | 该记录的检索来源（数据库名或补充来源），自由文本；不参与 `screen.py` 的计数计算，但供本文档「四、中文库回填路径」一节归类 | 自由文本，如 `Crossref`、`OpenAlex`、`PubMed`、`知网`、`万方`、`维普`、`手工补充-学位论文` | 必填 |
| 去重 | 去重判定结果 | `保留` / `重复（与序号 N）`（N 为对应保留行的序号） | 必填 |
| 标摘筛 | 标题摘要阶段的筛选结果 | `进入全文` / `排除` / `待定`；留空与 `待定` 同义（尚未筛完成） | 仅"去重 = 保留"的行必填；"去重 = 重复"的行不应填（见下「字段间依赖」） |
| 全文筛 | 全文阶段的筛选结果 | `纳入` / `排除` / `全文不可得`；留空表示尚未做出全文阶段判定 | 仅"标摘筛 = 进入全文"的行才可能有值；其余情况应留空（见下「字段间依赖」） |
| 排除理由码 | 全文阶段排除的理由代码 | 见下文「三、排除理由码表」（`E1`-`E5`、`E7`、`E9`，每行只填一个） | 仅"全文筛 = 排除"时必填；其余情况应留空 |
| 备注 | 自由文本 | 记录去重依据、待定原因、或排除理由码为 `E9` 时的具体理由说明等 | 选填 |

### 字段间依赖（组合合法性）

单看每一列的取值都合法，不代表整行合法。以下三条组合规则任一条违反，台账都过不了 `screen.py` 的校验（有的会被判定为「组合矛盾」而报错，有的会被识别为「筛选未完成」要求你先补完；具体退出码语义见 `SKILL.md`）。这类问题**不影响三条守恒等式**——光看等式是否平衡抓不出来，所以脚本另设 `logical_conflicts()` 专门检查：

1. **「去重」= `重复（…）`的行，「标摘筛」「全文筛」都应留空。** 已判重复的记录不应再进入后续筛选阶段；填了会被判定为组合矛盾。
2. **「标摘筛」为 `排除` / `待定` / 留空（尚未判定）的行，「全文筛」都应留空。** 这类记录尚未（或不会）进入全文阶段；若又有全文筛结果，说明台账有问题——但这三种子情形在 `screen.py` 里走的是两条不同的报错路径、退出码不同，不要混为一谈：
   - **标摘筛 = `排除`，全文筛却有值**（如又填了「纳入」）：这才是真正的组合矛盾——`count_stages` 会按标摘筛把它归入标摘排除，那个「纳入」就从统计里凭空消失，而三条守恒等式依然可能成立，所以要靠 `logical_conflicts()` 单独抓出来，**退出码 1**（判定为「台账校验失败」）。
   - **标摘筛 = `待定` 或留空，全文筛却有值**：`main()` 里 `pending_seqs()` 的检查先于 `logical_conflicts()`——只要台账中存在任意一行「标摘筛 ∈ {待定, 留空}」，就会先被判定为「筛选未完成」并整体提前返回，**退出码 2**，根本不会执行到 `logical_conflicts()`；即使这一行本身还带着一个此时无意义的全文筛「纳入」，报出来的提示也是「筛选未完成」而不是「组合矛盾」。这是有意的设计：标摘筛待定/留空是筛选流程正常的中途状态，还在正常筛选中的台账不该被误报为「台账有错」；只有标摘筛已经填了确定值（如「排除」）却仍与全文筛冲突，才算得上自相矛盾。
3. **「全文筛」= `排除` 的行，「排除理由码」必须非空。** PRISMA 2020 的硬性要求：全文阶段排除必须报告理由。

「去重」列圆括号里的「与序号 N」只是供人工追溯的可读信息——`screen.py` 只按"是否以「重复」二字开头"判定去重状态，不会校验 N 是否真的对应表中某一行，请自己确保对应关系正确。

### 示例（可直接用 screen.py 验证）

| 序号 | 题录锚点 | 来源库 | 去重 | 标摘筛 | 全文筛 | 排除理由码 | 备注 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 1 | Crossref | 保留 | 进入全文 | 纳入 |  |  |
| 2 | 2 | Crossref | 保留 | 进入全文 | 纳入 |  |  |
| 3 | 3 | 知网 | 重复（与序号 1） |  |  |  | 与序号 1 同一研究的中文版 |
| 4 | 4 | OpenAlex | 保留 | 排除 |  |  | 主题不符 |
| 5 | 5 | OpenAlex | 保留 | 进入全文 | 排除 | E4 |  |
| 6 | 6 | 万方 | 保留 | 进入全文 | 全文不可得 |  |  |
| 7 | 7 | PubMed | 保留 | 进入全文 | 排除 | E1 |  |

这 7 行对应的计数：识别 7 → 去重删除 1、去重后 6 → 标摘排除 1、进入全文 5 → 全文不可得 1、全文排除 2（`E1` × 1、`E4` × 1）、纳入 2。三条守恒等式与组合矛盾检查在这份数据上都通过。

## 二、三个纳排标准框架（陈列，由你逐条拍板）

以下三套框架是系统综述里常见的纳排标准结构，分别更适配不同的研究类型。这里只陈列各框架的常见要素与一条示例，**用哪个框架、每条要素具体怎么界定，都由你决定**；本文档不作选择、也不对框架排序。

### PICO（干预性研究）

**适用场景**：研究问题是"某干预是否 / 如何影响某结局"的实证型、干预性研究（如实验、准实验、随机对照试验的系统综述）。

| 要素 | 含义 |
| --- | --- |
| P | 研究对象（Population） |
| I | 干预（Intervention） |
| C | 对照（Comparison） |
| O | 结局（Outcome） |

**示例**（RQ：「ChatGPT 是否提高大学生的论文写作效率」）：

- P：大学生（本科生 / 研究生）
- I：使用 ChatGPT 辅助论文写作
- C：不使用 ChatGPT（传统写作方式或使用其他工具）
- O：论文写作效率（如完成时长）、写作质量评分

以上四项是 PICO 的常见陈列要素，每项具体如何界定、是否采用 PICO，由你逐条拍板。

### PICoS（定性研究）

**适用场景**：研究问题关注某现象的体验 / 意义 / 过程的定性研究系统综述。

| 要素 | 含义 |
| --- | --- |
| P | 研究对象（Population） |
| I | 感兴趣的现象（Interest） |
| Co | 情境（Context） |
| S | 研究设计（Study design） |

**示例**（RQ：「大学生如何体验使用 ChatGPT 辅助学术写作的过程」）：

- P：大学生（有 ChatGPT 辅助写作经历者）
- I：使用 ChatGPT 辅助学术写作的体验与顾虑
- Co：中国高校本科 / 研究生学术写作情境
- S：质性访谈研究 / 现象学研究

以上四项是 PICoS 的常见陈列要素，每项具体如何界定、是否采用 PICoS，由你逐条拍板。

### SPIDER（混合方法）

**适用场景**：证据既包含量化又包含质性研究的混合方法系统综述。

| 要素 | 含义 |
| --- | --- |
| S | 样本（Sample） |
| PI | 感兴趣的现象（Phenomenon of Interest） |
| D | 设计（Design） |
| E | 评价（Evaluation） |
| R | 研究类型（Research type） |

**示例**（RQ：「ChatGPT 对大学生学术写作效率与体验的影响有何证据」，整合量化与质性研究）：

- S：大学生（本科生 / 研究生）
- PI：ChatGPT 辅助学术写作对效率与体验的影响
- D：混合方法研究（问卷 + 访谈 / 准实验 + 质性追踪）
- E：写作效率指标、写作质量评分、学生自评体验
- R：定量、定性、混合方法研究均在可纳入的研究类型范围内

以上五项是 SPIDER 的常见陈列要素，每项具体如何界定、是否采用 SPIDER，由你逐条拍板。

## 三、排除理由码表

以下代码只在「全文筛」= `排除` 时使用（标题摘要阶段的排除不要求填理由码，见上文「字段间依赖」）。**每行只填一个代码**：若某文献同时符合多条排除理由，选其中最主要的一条填入——`screen.py` 按这一列的完整字符串统计分布，填多个代码（如用顿号或逗号连接）会被当成一个新的组合键，无法归入任何单一代码的统计。

| 代码 | 含义 |
| --- | --- |
| `E1` | 人群不符 |
| `E2` | 干预不符 |
| `E3` | 结局不符 |
| `E4` | 研究设计不符 |
| `E5` | 语言不符 |
| `E7` | 重复报告 |
| `E9` | 其他（用户填写具体理由，写入台账「备注」列） |

> 码表**不设「全文不可得」一项**，故编号跳过 `E6`。「全文不可得」在 PRISMA 2020 流程图里是独立一栏（Reports not retrieved），不是一种排除理由——它已由台账 `全文筛` 字段的独立取值 `全文不可得` 承载。二者混填（例如把「全文不可得」也编个 `E6` 码填进「排除理由码」列）会让流程图两栏重复计数：一次算进「全文不可得」栏，一次又算进「全文阶段排除」栏。

同理，`E8` 目前也未分配（保留、暂无用途），不要为凑连续编号而给它强加含义。

**`E7` 与「去重」列的「重复」不是一回事**：「去重」列的「重复」是标题摘要筛选之前的机械查重（同一题录被多个数据库重复命中，或标题 / DOI 基本一致）；`E7`「重复报告」是全文评估之后才发现的"同一研究的另一次报告"（如同一研究先发会议论文、后出期刊论文，题目作者不完全一致、机械查重认不出），只有读了全文才能判断，因此走「全文筛 = 排除 + 排除理由码 = E7」，而不是回头去改「去重」列。

## 四、中文库回填路径

知网 / 万方 / 维普三大中文数据库均**无免费开放 API**，`paper-search` 已把这道限制处理为「生成检索方案 → 你执行检索 → 回填题录」的引导路径（见 [`paper-search/references/知网万方检索方案模板.md`](../../paper-search/references/知网万方检索方案模板.md)）。本命令复用同一条路径，不重复设计：

1. **检索方案**：`paper-search` 按知网万方检索方案模板生成检索式，你在知网 / 万方 / 维普界面实际执行检索。
2. **题录回填**：你把检索到的题录按模板回填进 `literature/文献笔记表.md`；该表的 `#` 列值即本台账「题录锚点」列引用的值。
3. **台账登记**：把回填条目逐行加入 `literature/筛选台账.md`，「来源库」列照记中文库名（如 `知网`、`万方`、`维普`），不改写、不归并为英文库名。

### 流程图归位规则

PRISMA 2020 流程图区分「数据库检索」与「其他来源」两类识别渠道。按「来源库」列的取值，归类规则如下：

| 来源库类型 | 流程图归位 |
| --- | --- |
| 知网 / 万方 / 维普等数据库检索（含 Crossref / OpenAlex / PubMed 等英文库） | 数据库检索 |
| 手工补充的学位论文库条目、会议论文集条目（非数据库检索得到） | 其他来源 |

当前 `scripts/screen.py` 的流程图渲染把"识别"呈现为单一合计数字，不自动拆分"数据库检索 / 其他来源"两栏；上表的归位规则供你在报告正文中对"识别"环节做文字细分说明（如"识别 n=50 篇，其中数据库检索 45 篇、其他来源补充 5 篇"），不是脚本自动产出的数字。

## SKILL.md 怎么用本文档

- **第 1 步（定纳排标准）**：陈列本文档「二、三个纳排标准框架」的要素表，供你逐条拍板选定框架与标准内容。
- **第 2 步（建台账）**：按本文档「一、筛选台账字段定义」的 8 列与允许取值建立 `literature/筛选台账.md`；全文阶段排除时按「三、排除理由码表」选码填入「排除理由码」列（码表编号不连续，原因见该节说明，不要自行补全缺号）。
- **中文库来源**：按「四、中文库回填路径」的流程回填知网 / 万方 / 维普题录，并按归位规则做报告正文的文字细分。

本文档是静态参考文档（非脚本），未来补充其他纳排标准框架或排除理由码时在此登记，`screen.py` 与 `SKILL.md` 按相对路径引用即可。
