# paper-daily 行为验收清单

> 本目录**不写 pytest**（提示词型 skill、无确定性逻辑可测；与 paper-topic / outline / logic / disclose / review / abstract 同构）。
> 行为验收靠人工跑过下面的清单 + [`多档输入模拟脚本.md`](./多档输入模拟脚本.md)。
> 每个场景跑完，对照「期望产物要点」与「红线命中点」两栏判定是否通过。

---

## 验收场景（8 个）

### 自动轨正常（3 个）

- [ ] **场景 1：完整输入**（topic/ 交棒 RQ + 用户补充空 + 自动轨正常）
  - **前置**：建 `topic/RQ澄清记录.md`（含一句 RQ 如"大模型 agent 在科研发现场景的方法路径"），`project.paper.yaml` 设 `discipline: 计算机科学`，search.py 模拟正常返回（或实跑、`network_status=online`）。
  - **期望产物要点**：`daily/YYYY-MM-DD.md` + `.html` + `.paper/.json` 三产物齐全；概览段含逐源命中数（Crossref / OpenAlex / Semantic Scholar / arXiv）+ 中文缺口提示原文；抢发检测段三档分组（高/中/低）、每条带 5 维概念比对徽章；新发泛读段 arXiv 自动轨正常、用户补充轨标"今日无补充"；行动段程序化陈列。
  - **红线命中点**：① 高/中/低标签旁必有重叠维数（如"3 维重叠"）、无"最该读"用语；② 中文缺口提示原文（"英文库没检索到 ≠ 没人研究过"）必现；③ JSON 的 `chinese_gap_declared: true`。

- [ ] **场景 2：入口轻量化**（无 topic/ 交棒 + 用户当轮提供 RQ）
  - **前置**：不建 `topic/`，`project.paper.yaml` 可有可无。
  - **期望产物要点**：skill 不要求用户先跑 `/paper-topic`，第 1 步直接收 RQ；流程正常推进、产物三段齐全。
  - **红线命中点**：① 目录约定是增强非依赖——`topic/` 缺失不阻塞；② RQ 必须来自用户当轮提供（不从 LLM 记忆编造）。

- [ ] **场景 7：全低相关**（抢发对照 + 新发自动轨均命中、但全部 ≤1 维重叠）
  - **前置**：用一个非常窄或非常新的 RQ（如"2026 年 7 月发表的关于 XXX 的论文"）。
  - **期望产物要点**：三档分组里高、中档为空、低档有命中；行动段"全部低相关 → 是否照常推进当前研究？"项 `activated: true`；**不情绪化劝阻**（禁用语扫描：不出现"已被抢发/做不了了/晚了/没有意义"）。
  - **红线命中点**：① 抢发检测不下"已被抢发"定性词——即使全部低相关，也只陈列；② 行动建议是疑问句式、不替用户拍板。

### 用户补充轨（2 个）

- [ ] **场景 3：多源混合补充**（用户补充轨有 PaperFlow 输出 + DOI + 截图文本混合）
  - **前置**：第 1 步 ③ 粘贴混合内容：一行 PaperFlow daily 输出的标题+作者+arXiv ID、一行单独 DOI、一段从截图 OCR 出来的乱序文本（含标题与作者但格式混乱）。
  - **期望产物要点**：skill 用 LLM 抽取三条结构化字段；前两条 `parse_status=ok`、第三条 `parse_status=partial_fields`（缺失字段标 null）；新发泛读段用户补充轨区块三条齐全、每条带 `用户补充` 来源标签（**不可谎称自动检索**）；`user_supplement_raw` 字段完整保留原文。
  - **红线命中点**：① 用户补充来源标签固定为"用户补充"、不可谎称自动检索（红线 2）；② 解析失败的字段标 null + 待人工核对、不凭 LLM 记忆补全（三条不变③）。

- [ ] **场景 5：补充解析失败**（用户粘的内容完全无法解析）
  - **前置**：第 1 步 ③ 粘贴一段无结构文本（如"昨天群里有人提到一篇论文好像是关于 transformer 的"）。
  - **期望产物要点**：该条 `parse_status=parse_failed`、新发泛读段用户补充轨显示 `[解析失败] <原文> — 待人工核对`；**绝不**编造标题/作者/DOI 顶替；`user_supplement_raw` 完整保留原文。
  - **红线命中点**：① 三条不变③——不凭记忆编造文献/DOI（关键）；② 失败如实标注、不静默丢条目。

### 降级（2 个）

- [ ] **场景 4：F2 断网降级**（search.py 返回 `network_status=offline`）
  - **前置**：模拟断网（或断开网络实跑），search.py 返回全源 timeout。
  - **期望产物要点**：MD/HTML 顶部插 `<div class="fallback-banner">` 醒目警示（"今日自动轨不可用：网络不通"）；**抢发检测整段省略**（不输出空表充数）；新发泛读段用户补充轨照跑；行动段改为"是否先跑 /paper-doctor" + "用户补充有高相关 → 是否进 /paper-search 深检？"；JSON 的 `fallback_declared: true`。
  - **红线命中点**：① 三条不变③——断网显式声明、不静默顶替；② 抢发段整段省略而非空表（不静默用空表误导用户）。

- [ ] **场景 8：F4 时间窗过滤失败**（arXiv API 只支持按年过滤）
  - **前置**：时间窗设"最近 3 天"，模拟 arXiv API 按天过滤不可用。
  - **期望产物要点**：自动轨 `--per-source` 从 50 调到 200（看 JSON 的 `args_fallback` 字段命中）、拉回今年所有结果、按 `submittedDate` 内存筛到 3 天内；自动轨区块顶部标注"已从今年前 200 篇中按日期筛到时间窗内 Z 篇，可能未覆盖全部"；**不可静默漏掉**时间窗内新发。
  - **红线命中点**：① 红线 2——覆盖方式必声明、漏检可能必如实标注；② 不静默缩小范围。

### 抢发命中（1 个，关键红线场景）

- [ ] **场景 6：抢发命中**（抢发对照轨返回 1 篇概念 4 维重叠）
  - **前置**：第 1 步 RQ 提供一个已有大量相关发表的方向（如"RAG 检索增强生成"），search.py 抢发对照轨返回 1-3 篇 ≥3 维重叠的论文。
  - **期望产物要点**：抢发检测段 🔴 概念高度重叠档有命中、每条带 5 维概念比对徽章（≥3 个 ✓）+ "高相关 · X 维"徽章；末尾固定话术"「是否仍可做」的判断归用户与导师"必现；行动段"🚨 抢发命中（高相关 ≥ 1）→ 是否进入 /paper-topic 重审 RQ？"项 `activated: true`；**禁用语扫描**（关键）：产物全文不出现 `已被抢发` / `做不了了` / `晚了` / `没有意义`。
  - **红线命中点**：① 三条不变②——抢发命中不夸大、不替用户下定论（**本场景是最关键的发布门**）；② 概念比对可追溯（每条标具体重叠维度）。

## 红线发布门自检（所有场景跑完后批量回扫）

跑完所有 8 个场景后，对所有产物 MD/HTML 跑一次批量自检：

```bash
# 红线 1：不替用户判研究价值、不排序
grep -rE "最相关|最重要|必读|Top.*推荐|最该读" daily/  # 期望空（仅允许出现在禁用语清单/越界话术段）

# 红线 2：覆盖方式必声明、中文缺口必提示
grep -L "英文库没检索到\|中文缺口" daily/*.md  # 期望空（每份日报必含原文）

# 三条不变②：抢发命中不下"已被抢发"定性词
grep -rE "已被抢发|做不了了|晚了|没有意义" daily/  # 期望空

# 三条不变③：完全降级时抢发段必须省略（不空表）
#   逐份检查：若顶部有 fallback-banner，则抢发检测段必须不存在
```

任一自检非空需返工、定位是 skill 提示词偏差还是 LLM 跑偏。
