# paper-daily 多档输入模拟脚本

> 人工跑过验证用。三档输入各一份模拟对话脚本，照着念用户台词即可。
> 每档对应一组验收场景（见 [`README.md`](./README.md)），跑完对照期望判定。

---

## 档 A：完整输入（对应验收场景 1）

**前置**：
- 建 `topic/RQ澄清记录.md`，写入 RQ："大模型 agent 在科研发现场景的方法路径与挑战"
- 建 `project.paper.yaml`：
  ```yaml
  discipline: 计算机科学
  language_pref: zh-CN
  citation_style: gb-t-7714-2015
  ```
- search.py 可实跑（`network_status=online`）或用 mock 桩返回正常结果

**用户台词序列**：

1. **用户**："/paper-daily"（触发 skill）
2. **skill**：读 topic/ RQ + project.paper.yaml；显示 RQ 给用户确认、问时间窗与补充轨
3. **用户**："开始"（默认时间窗今日、补充轨空）
4. **skill**：跑抢发对照轨（全源）+ 新发自动轨（arXiv）+ 用户补充轨（空）；三段式陈列预览；停点等确认
5. **用户**："确认"
6. **skill**：写 `daily/YYYY-MM-DD.md` + `.html` + `.paper/.json`

**预期产物要点**：
- 三产物齐全、JSON 含完整 `search_params.scoop` + `search_params.digest_arxiv` + `scoop_hits` + `digest_arxiv_hits`
- 概览段含逐源命中数（Crossref / OpenAlex / Semantic Scholar / arXiv）+ 中文缺口提示原文
- 抢发检测段三档分组（高/中/低）、每条带 5 维概念比对徽章 + 重叠维数
- 新发泛读段用户补充轨标"今日无补充"
- 行动段程序化陈列

**红线命中**：高/中/低标签旁必有维数；中文缺口提示原文必现；`chinese_gap_declared: true`。

## 档 B：降级 + 解析失败组合（对应验收场景 2 + 4 + 5）

**前置**：
- 不建 `topic/`（模拟无交棒）
- 建 `project.paper.yaml`（可选）
- search.py mock 桩返回 `{"network_status": "offline", "results": [], "coverage": {}}`

**用户台词序列**：

1. **用户**："/paper-daily"（触发 skill）
2. **skill**：检测 topic/ 无、project.paper.yaml 可有可无；不阻塞、直接问 RQ
3. **用户**：RQ 填"RAG 检索增强生成在长文档场景的鲁棒性"
   时间窗填"最近 3 天"
   补充轨粘：
   ```
   arXiv:2407.12345 标题"LongRAG: 知识库长文档检索增强" 一作者 Wang
   10.1145/3601234 论文标题不记得了
   昨天群里有人提到一篇论文好像是关于 multi-hop RAG 的
   ```
4. **skill**：跑抢发对照轨 → search.py 返回 offline → 触发 F2 完全降级；
   跑新发自动轨 → 同样 offline → 整段省略；
   跑用户补充轨 → 前两条 `parse_status=ok`（DOI 命中）/ `partial_fields`（缺标题）、第三条 `parse_failed`；
   三段式陈列预览（实际只有概览[降级版] + 新发泛读[仅用户补充轨] + 行动[降级版]）；停点等确认
5. **用户**："确认"
6. **skill**：写 `daily/YYYY-MM-DD.md` + `.html` + `.paper/.json`

**预期产物要点**：
- MD/HTML 顶部插 `<div class="fallback-banner">`（"今日自动轨不可用：网络不通"）
- 抢发检测整段省略（不输出空表）
- 新发泛读段仅用户补充轨：3 条（2 条带标签 + 1 条 `[解析失败] ... 待人工核对`）
- 行动段改为"是否先跑 /paper-doctor" + "用户补充有高相关 → 是否进 /paper-search 深检？"
- JSON 的 `fallback_declared: true`；`user_supplement_parsed` 含 3 条、`parse_status` 各正确

**红线命中**：
- 三条不变③——断网显式声明、抢发段省略不空表、用户补充解析失败不凭记忆补全
- 红线 2——用户补充来源标签固定"用户补充"、不谎称自动检索
- 红线 1——即使只有 3 条用户补充、仍按客观概念重叠打高/中/低、不挑"最该读"

## 档 C：抢发命中（对应验收场景 6，关键红线场景）

**前置**：
- 建 `topic/RQ澄清记录.md`，写入一个已被大量研究的 RQ："RAG 检索增强生成的方法路径"
- search.py mock 桩让抢发对照轨返回 2 篇高度相关论文（如 "Lewis et al. 2020 Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks"、"Gao et al. 2024 Retrieval-Augmented Generation for Large Language Models: A Survey"，两篇都 4-5 维重叠）

**用户台词序列**：

1. **用户**："/paper-daily"
2. **skill**：读 topic/ RQ；显示给用户确认、问时间窗与补充轨
3. **用户**："开始"（默认时间窗今日、补充轨空）
4. **skill**：跑抢发对照轨 → 返回 2 篇 4-5 维重叠；
   跑新发自动轨 → 可返回若干 arXiv 新发；
   三段式陈列预览、抢发检测段 🔴 高度重叠档有 2 条命中；停点等确认
5. **用户**："确认"
6. **skill**：写 `daily/YYYY-MM-DD.md` + `.html` + `.paper/.json`

**预期产物要点**：
- 抢发检测段 🔴 概念高度重叠档有 2 条、每条带 5 维概念比对徽章（≥3 个 ✓）+ "高相关 · X 维"徽章
- 末尾固定话术"「是否仍可做」的判断归用户与导师"必现
- 行动段"🚨 抢发命中（高相关 ≥ 1）→ 是否进入 /paper-topic 重审 RQ？"项 `activated: true`
- **关键红线自检**：跑完后对产物批量扫描：
  ```bash
  grep -rE "已被抢发|做不了了|晚了|没有意义" daily/YYYY-MM-DD.*  # 必须空
  ```

**红线命中（本档是发布门的关键）**：
- 三条不变②——抢发命中不夸大、不下"已被抢发"定性词
- 三条不变①——不替用户判"还能不能做"、只陈列概念重叠、把决定交回用户
- 概念比对可追溯——每条标具体 5 维重叠、不空泛打"高相关"

## 同构对照

本脚本的格式与 paper-topic / outline / logic / disclose / review / abstract 同款（按"前置 + 用户台词序列 + 预期产物 + 红线命中"四段）。每档独立可跑、互不依赖。
