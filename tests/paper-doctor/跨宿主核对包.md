# paper-doctor 跨宿主验证核对包

| 项 | 内容 |
| --- | --- |
| 用途 | 补跑 paper-doctor 发布门「跨宿主验证」（[tests README](README.md) · spec §9.1） |
| 门定义 | ≥2 宿主各触发一次 `/paper-doctor` 并**产出一致**，含「断网宿主上报 `offline` 并显式声明核验不可用」 |
| 宿主 A | Claude Code（基线见下，`overall=degraded`） |
| 宿主 B | Codex CLI（2026-07-23 实测，`overall=offline`，沙箱网络受限触发） |
| 结论 | **通过**——判定层五项「必须一致」全吻合；断网 offline 强制子项由宿主 B 真实命中并正确处理 |

> **一致性口径先说清**：两宿主消费的是同一份确定性脚本 `scripts/doctor.py` 与同一套判定逻辑（`probe.py` 的 `CORE_IDS` + `ProbeEngine.overall()`）。因此**判定逻辑对同环境必然一致，但具体读数随环境变**——某台机器配了 key、某台网络能通 pubmed，都会让 JSON 逐字节不同。所以「一致」判的是**判定层**（态码 + 判定依据 + 报告结构 + 断网出口），不是要求两份 JSON 完全相同。下方 A / B 两栏对照，只对「必须一致」项打勾。

## 宿主 A 基线（Claude Code，真实产出）

- 触发：`python3 skills/paper-doctor/scripts/doctor.py`
- `overall`: **`degraded`**
- 判定依据：核心源（`CORE_IDS = crossref / openalex / semantic_scholar / arxiv`）非全 ok（`semantic_scholar` 因无 `SEMANTIC_SCHOLAR_API_KEY` 判 `partial`），也非全 unavailable → 按 `overall()` 短路规则落 `degraded`。
- `runtime`: python_version ok（3.11.9）/ sqlite3 ok / shared_import ok
- `credentials`: PAPER_MAILTO、SEMANTIC_SCHOLAR_API_KEY、NCBI_API_KEY 均 missing（可选，不拉低整体）
- `network`: ok（依据核心源可达性推断，不额外发请求）
- `cache`: ok（`~/.cache/paper/datasources.db` 目录可写）
- `datasources`: crossref/openalex/arxiv = ok(core)；semantic_scholar = partial(core)；pubmed/eric = unavailable(supplementary，不拉低)；doi_ra = unavailable(role=core 但不在 CORE_IDS，无客户端实现，按设计不参与判定)
- `datasources_overall`: `degraded`
- SKILL.md 报告呈现：顶部应给一句「可用但有降级 → 建议先补 X」的中文结论 + 行动指引（对应 spec §7.2）

## 在宿主 B 怎么跑

1. 在第二宿主里把仓库打开，正常触发 `/paper-doctor`（让宿主自己按 SKILL.md 走「跑脚本 → 读回 JSON → 呈现中文结论」的路径；这正是要验的行为，别绕过 SKILL.md 直接手敲脚本）。
2. 把宿主 B 的**完整 JSON** 与**顶部中文结论那一句**贴回来给我。
3. 若第二宿主**无法执行脚本**（无 Bash / 禁子进程）——这不是失败，恰是要验的降级出口：确认它是否**显式声明「本宿主无法运行体检脚本，环境探测不可用」并给出手动核对清单**（Python 版本 / 三个环境变量 / 缓存目录权限），而非凭记忆报「就绪」。把它的这段声明贴回来即可。

## 一致性核对表（2026-07-23 据宿主 B 实测逐行判）

| 核对项 | 必须一致？ | 宿主 A（Claude Code） | 宿主 B（Codex CLI） | 判定 |
| --- | --- | --- | --- | --- |
| 报告结构（runtime/credentials/network/cache/datasources/overall 六段齐全） | ✅ 必须 | 齐全 | 六段齐全（运行时/数据源/网络/凭证/缓存 + 顶部结论） | ✅ 一致 |
| `overall` 态码判定**规则**（同环境同输入 → 同结论） | ✅ 必须 | degraded（核心源非全 ok 非全 unavail） | offline（核心源**全**不可达，`Operation not permitted`）→ 严格按 `overall()` 规则 | ✅ 规则一致、各自自洽 |
| 顶部中文结论与态码对应（就绪/可用但有降级/核验不可用/环境未就绪） | ✅ 必须 | 「可用但有降级」 | 「❌ 核验不可用：核心数据源全不可达」+ 指引联网重跑 | ✅ 对应正确（offline→核验不可用） |
| CORE_IDS 判定口径（doi_ra 不参与、补充源不拉低） | ✅ 必须 | 符合 | doi_ra 明标「无客户端实现（正常）」；pubmed/eric 标补充源 | ✅ 一致 |
| 「体检不代修」——只给 fix 指引不执行修复 | ✅ 必须 | 符合（脚本只读） | 通篇只给 fix 指引（export 配法、设 `PAPER_CACHE_DIR`），未执行修复 | ✅ 符合 |
| 具体 `overall` 值 | ⬜ 可不同 | degraded | offline | 随环境（B 沙箱核心源全断），依据自洽即算一致 |
| 各数据源 ok/partial/unavailable 具体值 | ⬜ 可不同 | 见基线（多数 ok） | 全 unavailable（`Operation not permitted`） | 随 B 沙箱网络 |
| 凭证 missing / present 具体值 | ⬜ 可不同 | 三项 missing | 三项 missing | 恰好相同（两宿主都未配可选凭证） |
| 缓存可写 | ⬜ 可不同 | ok（目录可写） | ❌ 不可写（沙箱权限，同源于 `Operation not permitted`） | 随 B 沙箱，属环境差异，不影响判定层一致 |

## 断网子项（门定义强制项）

| 核对项 | 期望 | 宿主 B（Codex CLI 实测） | 判定 |
| --- | --- | --- | --- |
| 断网 / 核心源全不可达时 overall | `offline` | `offline`（核心源全 `Operation not permitted`） | ✅ |
| 断网时是否**显式声明核验不可用**（而非静默降级/凭记忆报就绪） | 是 | 「❌ 核验不可用：核心数据源全不可达」，并诚实区分「沙箱网络限制、非真实断网……联网重跑即可」 | ✅（且额外区分了根因，未静默降级） |

> **断网子项在真实第二宿主上自然命中**：宿主 B（Codex CLI）沙箱网络受限，核心源全不可达是真实环境产生的输入，doctor 正确输出 offline + 显式声明核验不可用——比在宿主 A 人为断网复现更有说服力。故断网验证不再需要在宿主 A 补做。（宿主 A 侧 offline 判定逻辑另有单测场景 5 覆盖。）
