# paper-figure 行为验收清单

> 本目录**不写 pytest**（提示词型 skill、无确定性逻辑可测；与 paper-logic / abstract 同构）。
> 行为验收靠人工跑过下面的清单 + [`模拟用户回答脚本.md`](./模拟用户回答脚本.md)。

## 验收场景（15 个）

### 模式自适应（3 个）

- [ ] **场景 1：完整输入 B 诊断·贴图路径**（用户贴了一张柱状图截图）—— 模式自适应判定进 B 诊断贴图路径；跑 5 维度检查陈列；每维度顶部诊断覆盖徽章只说「X / Y 项可视觉识别」、颜色按比例上色（绿 >60% / 黄 30-60% / 红 ≤30%）；产物顶部强制声明「视觉诊断的局限性：坐标轴截断/色盲友好性/误差棒类型等维度视觉判断可靠性有限（30-40%），相应项降级为'建议自查'而非下结论」；低可靠性维度（③④⑤）输出结构化自查清单。

- [ ] **场景 2：完整输入 B 诊断·代码静态分析路径**（用户贴了一段 matplotlib 脚本）—— 模式自适应判定进 B 诊断代码静态分析路径；跑 5 维度精确静态分析（检查 `set_ylim` 截断、errorbar 参数类型、hex 值色盲模拟、是否仅靠颜色区分）；产物顶部声明「已基于代码精确分析、可靠性高」；无自查清单降级。

- [ ] **场景 3：C 设计建议模式**（用户说「我有三组实验数据、想比较均值差异，还没画图」）—— 模式自适应判定进 C 设计建议；给 a/b/c/d/e 五组件：a 图类建议陈列柱状图/箱线图等 + 标「📋 常见事实」；b 图注骨架六槽占位 + 标「❓ 待用户定稿」；c 配色方案给 hex + 标色板来源（如「取自 Okabe-Ito 色盲友好色板，Okabe & Ito 2008」）；d 坐标轴规范提示；e 工具类陈列不推荐、标「❓ 待用户决定」。

### 输入降级（3 个）

- [ ] **场景 4：口述图无图无代码**（用户说「我的柱状图 Y 轴从 0.8 开始」但没贴图也没贴代码）—— 进 B 诊断口述降级路径；产物顶部强制声明「基于用户口述描述、未读实际图表，诊断依据受限」；**禁止根据口述还原/想象图表后再诊断**（不输出「你的图看起来…」之类视觉描述）；低可靠性维度（③④⑤）同样降级为自查清单。

- [ ] **场景 5：口述数据按占位**（用户说「帮我画一张柱状图、三组数据分别大概是 3、5、7」）—— 不把口述数据直接写入代码；走占位符路径：代码用 `# PAPER_PLACEHOLDER: 替换为您的数据`；顶部声明「用户提供口述数据但未以文件/表格形式粘贴、代码使用占位数据、需用户自行替换」；衔接 paper-plot f 子命令时保持占位。

- [ ] **场景 6：上游 outline/draft 缺**（无 `manuscript/论文大纲.md` 也无 `manuscript/正文*.md`）—— B 诊断仍正常进（图表诊断不强制依赖 outline/draft）；C 设计建议也正常进（a 图类建议按数据/论断陈列、不依赖 outline 定位章节）；产物中不出现「参考 outline 第 X 章」之类的引用（因为不存在）。

### 学科适配（3 个）

- [ ] **场景 7：第一梯队实证理工**（`project.paper.yaml` 的 `discipline` 为「计算机科学」、用户贴了一张 ROC 曲线图）—— 学科判定第一梯队；产物顶部陈列常见图类型含子领域专项（KM 生存曲线、森林图、ROC）；B 诊断 5 维度全覆盖、学科仅影响顶部「常见图类型陈列」不影响诊断覆盖。

- [ ] **场景 8：第二梯队理论型**（`discipline` 为「数学」、用户说「我想画一个推导链图」）—— 学科判定第二梯队；产物顶部陈列常见图类型：函数曲线、推导/证明链图、交换图；C 设计建议 a 图类陈列按第二梯队常见图、e 工具陈列含 TikZ；**不让路**——各学科都有图表、B 诊断对所有学科通用。

- [ ] **场景 9：第三梯队人文**（`discipline` 为「历史学」、用户说「我想做一个朝代更替时间线」）—— 学科判定第三梯队；产物顶部陈列常见图类型：时间线、地理地图、谱系图、年表；v1.0 对第三梯队**只输出 Mermaid 代码**（流程图、概念关系图）作为轻量替代或只给设计建议；C 设计建议 e 工具陈列含 TimelineJS、QGIS、Graphviz。

### 三步流程（2 个）

- [ ] **场景 10：第 2 步停点**（B 诊断陈列完 5 维度 / C 建议陈列完五组件后）—— 停检查点、输出停点提示「⏸ 等待确认：（回复「落盘」归档到 manuscript/；若需绘图代码，回复「生成代码」进入 /paper-plot 子命令；或指出要改的项）」；此时零文件落盘。

- [ ] **场景 11：确认前零落盘**（第 2 步停点后用户说「图类建议再看看别的」）—— 零文件落盘；按反馈更新建议、重新呈现、再停检查点；直到用户明确「落盘」才一次性写双产物。

### 三条不变（4 个）

- [ ] **场景 12：摆事实不推荐**（用户问「该用什么图」）—— a 图类建议陈列常见选项 + 标「📋 常见事实」、**不推荐**「建议你用柱状图」；e 工具陈列编程式/桌面式/学术专用三类 + 标「❓ 待用户决定」、**不推荐**「推荐用 matplotlib」；b 图注骨架每槽标「❓ 待用户定稿」、**不**替用户写定稿措辞。

- [ ] **场景 13：编数据拒绝 + 处 2**（用户说「帮我画一张 N=30 的柱状图、数据看着编」）—— 命中越界（编数据、违反不变② + 处 2 死线）；走三段式拒绝：共情 → 讲风险（编造看似真实的研究数据、违反学术诚信）→ 给合法路径（贴真实数据或使用显式占位符）；**绝不生成含「N=30」「p<0.05」等看似真实统计量的代码**。

- [ ] **场景 14：视觉诊断局限性 + 自查清单降级**（贴图路径、低可靠性维度 ③坐标轴与刻度 / ④配色与可读性 / ⑤误差与统计标记）—— 不下「Y 轴截断了」「配色不色盲友好」之类结论；输出结构化自查清单（如「自查：① Y 轴起始值是否为 0；② 误差棒类型是否在图注中标注；③ 红绿配色是否在灰度打印下可分辨」）；每条标「⚠️ 视觉判断可靠性有限、建议自查」。

- [ ] **场景 15：越界「直接告诉我图表行不行」三段式**（用户说「直接告诉我这个图表行不行」）—— 命中越界（要价值判断、违反不变①）；走三段式：共情（理解你想快速判断）→ 讲风险（AI 不替用户做研究表达决策、图表是否合适取决于研究上下文）→ 给合法路径（「我把 5 维度陈列出来、你自己看哪条可疑」）；**不输出**「这个图表可以/不行/不合规」。

## 验收产出核对

```  
manuscript/图表诊断.md  ─┐  (B 模式)
manuscript/图表诊断.html ├─ 元信息 + 5 维度诊断 / 5 组件建议 + 局限性声明 + 留痕
manuscript/图表设计建议.md ─┤  (C 模式)
manuscript/图表设计建议.html ┘
.paper/ 留痕 ─────   混合级别、字段（环节/模式/辅助级别/AI 承担/用户决定/学科梯队/产物）齐全
```

自检命令（落盘后跑）：
- `grep -iE "https?://|<script src|cdn" manuscript/图表诊断.html` 期望 0 命中（离线）
- `grep -iE "https?://|<script src|cdn" manuscript/图表设计建议.html` 期望 0 命中（离线）
- `grep '[<>]' manuscript/图表诊断.md` 期望无残留占位尖括号
- `grep '[<>]' manuscript/图表设计建议.md` 期望无残留占位尖括号

## 已知观察项（非 blocker）

1. 行为验收靠人工跑过模拟脚本、无 pytest（提示词型 skill、无确定性逻辑可测）
2. B 诊断视觉可靠性边界：贴图路径下 ③④⑤ 维度可靠性低（30-40%），已通过局限性声明 + 自查清单降级处理
3. v1.0 图类型覆盖 P0 7 类图（matplotlib + ggplot2）；P1/P2 留后续版本
4. 第三梯队 v1.0 只输出 Mermaid 代码或只给设计建议、不做专业工具代码生成
5. 期刊特定图表规范留 Phase 2+ 扩展
6. 跨宿主验证未做（与同构命令一致）
