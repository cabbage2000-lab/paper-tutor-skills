# paper-outline 行为验收清单

> 本目录**不写 pytest**（提示词型 skill、无确定性逻辑可测；与 paper-topic 同构）。
> 行为验收靠人工跑过下面的清单 + [`模拟用户回答脚本.md`](./模拟用户回答脚本.md)。

## 验收场景（10 个）

### 输入降级（3 个）

- [ ] **场景 1：完整输入**（RQ + 文献笔记都有）—— 产物每章要点尽量挂真实锚点、顶部徽章按阈值上色。
- [ ] **场景 2：缺文献笔记**（RQ 在、`literature/` 空）—— 大纲照产，每条无支撑要点标「⚠️ 无文献支撑、纯结构占位」、顶部强制覆盖声明。
- [ ] **场景 3：缺 RQ**（用户口头也给不出）—— 让路 `/paper-topic`，不裸搭骨架。

### 四停点流程（4 个）

- [ ] **场景 4：第 1 停点选骨架** —— 摆 1-2 个学科常见骨架（明示"非推荐"）、等用户确认才进下一步。
- [ ] **场景 5：第 2 停点起草草案** —— 起草完整章节、每章 3-5 条要点、挂锚点、顶部出锚点覆盖声明、等用户确认。
- [ ] **场景 6：第 3 停点逐章修订** —— 用户提修改 → 完整重新呈现 → 再停检查点；循环到明确"确认"。
- [ ] **场景 7：确认前零落盘** —— 修订循环中无任何文件写入；只有用户"确认"后才一次性落盘。

### 三条不变（3 个）

- [ ] **场景 8：结构取舍由用户拍板** —— 用户选了骨架又大改成完全自定义版本 → 以用户版本为准、不强归回骨架、HTML 页脚据实记自定义。
- [ ] **场景 9：锚点不造假** —— 用户要求"挂 Smith 2024"但笔记表没这条 → 不挂、提示用 search/verify 补、绝不编锚点。
- [ ] **场景 10：产物只记用户拍板的结构** —— 被否决的章节单列「被否决的章节」节如实记、不混进主结构。

## 越界转化（附加）

- [ ] **"直接帮我把大纲定下来别问了"** —— 命中越界：走三段式（共情 → 讲风险 → 给 5 分钟第一步），不替用户定结构。
- [ ] **"帮我把每章正文写出来"** —— 命中越界：让路 `/paper-draft`（开发中）。
- [ ] **"基于我的 RQ 起草一份大纲草案"** —— 不命中越界：直接进第 1 步流程。
