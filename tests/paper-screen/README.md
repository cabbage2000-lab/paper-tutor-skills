# paper-screen 行为验收清单

> 与 logic / outline / disclose 等纯提示词 skill **不同**：本目录**有** pytest——
> [`test_screen.py`](./test_screen.py) 35 条，覆盖确定性内核 `scripts/screen.py` 的
> 解析 / 分级计数 / 守恒校验 / 组合矛盾检查 / 待定检测 / 渲染 / CLI 退出码。
>
> 跑法：`python3 -m pytest tests/paper-screen/ -q -p no:asyncio`
>
> **但提示词层的行为**（停点、陈列口径、让路、越界转化）无法用 pytest 覆盖——
> 那部分靠人工跑过下面的清单 + [`模拟用户回答脚本.md`](./模拟用户回答脚本.md)。

## 验收场景（14 个）

### 输入降级（3 个）

- [ ] **场景 1：完整输入**（`literature/文献笔记表.md` + `检索日志.md` 都在）—— 定标准 → 建台账 → 逐篇陈列对应事实 → 用户拍板 → 出图 → 落四份产物（台账 / 报告 HTML+MD / 数据提取表 / 偏倚清单）。
- [ ] **场景 2：缺笔记表** —— 让路 `/paper-search` 先检索；**零文件落盘、绝不自行编文献**。
- [ ] **场景 3：笔记表缺 DOI / 标题不全** —— 台账照建；去重仅按可比字段，产物顶部声明「去重依据不完整，可能有漏判重复」。

### 学科适配（2 个）

- [ ] **场景 4：第二梯队理论型** —— 台账与流程图照走；**偏倚评估整块省略、不产空表**，报告顶部写明让路原因；PRISMA 27 项自查**仍整块渲染**，仅第 11、18 项可标「不适用」。（这两种让路粒度不是一回事，验收时分别确认）
- [ ] **场景 5：第三梯队人文** —— **整体让路**：说明 PRISMA 通常不适用于人文综述，仅保留检索日志与去重台账，不产流程图与自查表；写让路留痕。

### 脚本四态退出码（4 个）——本命令的立身之本，必须逐态验

- [ ] **场景 6：退出码 0** —— 台账干净 → SVG 整段内嵌进 HTML 的 `PRISMA_SVG_SLOT` 槽位，四份产物落盘。
- [ ] **场景 7：退出码 1 · 守恒不平** —— 手工把某行「去重」列改成规定取值外的值（如「去除」）→ agent **不出图、不落盘**，原样转述不平等式与差额，请用户核对取值。
- [ ] **场景 8：退出码 1 · 组合矛盾** —— 手工造一行「标摘筛=排除」却又填「全文筛=纳入」→ 该台账**三条守恒等式全部成立**，必须由组合矛盾检查拦下；agent 不得把它说成「守恒失败」。
- [ ] **场景 9：退出码 2 · 筛选未完成** —— 台账留一行「待定」→ agent 转述待定序号、回到第 2 步继续筛；**不得说成「台账有错」**（这是正常中途状态）。
- [ ] **场景 10：退出码 3 · 台账读不到** —— 路径写错 → agent 说「不是台账内容问题、核对路径」，不去让用户排查筛选数据。

### 三条不变（3 个）

- [ ] **场景 11：不替用户判纳排** —— 逐篇陈列全程只给「该文与各条标准的对应事实」+ ❓；产物全文 grep「建议纳入 / 建议排除 / 符合纳入条件」应 0 命中。
- [ ] **场景 12：计数不靠模型** —— agent 全程不手写任何一个 PRISMA 计数；用户说「数字对不上你直接改成对的」时明确拒绝，并陪用户回台账找填错的行。
- [ ] **场景 13：不编文献不编理由** —— 台账每行的题录锚点都能在笔记表里找到对应 `#` 序号；排除理由是用户原话或用户选的码，agent 不替编「像样点」的理由。

### 越界转化（2 个）

- [ ] **场景 14：自动筛 / 元分析统计** —— 「你帮我决定纳入哪些」「按标准自动筛一遍」走三段式转化；「顺手算个合并效应量 / 异质性 I²」走让路说明（指路 R 的 `meta`/`metafor` 或 RevMan，森林图绘制指 `/paper-plot` v1.1+）。

## 已知观察项（非 blocker，随 commands.yaml 注释同步）

1. 行为验收靠人工跑本清单（确定性内核有 35 条 pytest）。
2. 去重靠 DOI 与标题规范化比对——同一研究的会议版 / 期刊版机器判不出，需用户手工标 `E7`。
3. 流程图识别框如实标「记录总数」、未拆「数据库检索 / 其他来源」两栏（拆栏留后续；references 的归位规则定位为供报告正文做文字细分）。
4. `logical_conflicts()` 里对「待定」的分支在 CLI 执行路径上不可达（`pending_seqs()` 先返回 2）——作为库函数直接调用时仍有效。
5. 跨宿主验证未做（第二宿主待跑）。
