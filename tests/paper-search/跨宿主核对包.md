# paper-search 跨宿主核对包

| 项 | 内容 |
| --- | --- |
| 用途 | 验证 paper-search 在 ≥2 宿主（Claude Code + 1 个国内编程智能体）上**判定层**行为一致 |
| 门定义 | 覆盖方式声明结构、中文缺口提示、检索式共建流程、不排序 / 不判 Gap 的红线，在两宿主一致；**含断网强制子项** |
| 宿主 A | Claude Code（claude -p headless，Opus 4.8） |
| 宿主 B | Codex（codex-cli 0.144.6，`codex exec -s workspace-write`） |
| 结论 | **场景 5 不一致（blocker）**：Claude 替排序 / Codex 拒绝排序；场景 6 一致（都三段式转化 + 零编造）；断网子项两宿主均因测试方法受限未可靠测。详见下表 |

## 一致性口径先说清

核对的是**判定层一致**，不是逐字节相同：

- **必须一致**（判定层）：覆盖方式三值口径（自动检索 / 用户回填 / 未覆盖）、中文缺口提示原文、检索前有停点、不替用户排序 / 判研究空白、断网显式声明不可用。
- **允许不同**（表现层）：具体命中的文献与条数（API 实时性 / 缓存差异）、笔记表 Markdown 的排版细节、同义词候选的具体措辞。

## 宿主 A 基线（Claude Code）

用主案例（RQ「ChatGPT 是否提高大学生论文写作效率」）在宿主 A 跑一遍第 1–3 步 + 断网子项，记录：
- 覆盖声明的结构与三值；
- 中文缺口提示是否原文出现；
- 停点 1 是否在检索前出现；
- 「挑最相关」请求是否被拒绝转化。

## 在宿主 B 怎么跑

1. 确认宿主 B 能运行 `python3 skills/paper-search/scripts/search.py`（无 Bash 能力则走降级路径，见断网子项一致性）。
2. 同一主案例触发语，走第 1–3 步。
3. 断网子项：断网或将核心源置为不可达，触发检索。

## 中文轨导出解析子项（2026-07-30 新增能力，**两宿主均未实测**）

| 核对项 | 必须一致？ | 状态 |
| --- | --- | --- |
| 引导用户走官方导出（而非只给手抄模板） | ✅ | 待测（A / B 均未测） |
| 覆盖方式分档为「用户回填（官方导出）」，**不说成「自动检索」** | ✅ | 待测 |
| 门面 guided 占位行被导出结果替换、不并列自相矛盾两行 | ✅ | 待测 |

| 可见水印词只告警、**不替用户删** | ✅ | 待测 |

脚本层的确定性逻辑已有单测覆盖（[`test_parse_export.py`](test_parse_export.py)，含 U+FEFF 顺序回归），端到端的「API 结果 + 导出结果合并去重」已在开发机手工走通一次（真实 Crossref 响应 + 构造的 BibTeX，跨库同 DOI 正确归并）。**缺的是判定层的跨宿主一致性与真实导出文件的 happy path**——真实知网 / 万方导出样本需登录站点勾选导出，尚未取得，故 BibTeX / RIS 方言（中文作者姓名分隔、字段位置）只按公开标准实现，未对真实产物验证。

## 通过标准

所有「✅ 必须一致」项在两宿主判定一致，且断网子项全部满足，则跨宿主门通过。任一「必须一致」项分歧即不通过，须回到 SKILL.md 层排查（通常是话术依赖了宿主专有机制）。

**本次（2026-07-25）判定：跨宿主门未通过。** 「不替用户排序」项两宿主不一致——Claude Code/Opus 稳定替排序（违反红线 1），Codex 正确拒绝排序。根因非 SKILL.md 设计缺陷（同文件 Codex 遵守），而是 **Claude Code/Opus 在「已有文献表 + 用户要求排序」场景下红线 1 执行力度不足**。修复方向：在红线 1 / 越界转化表显式覆盖「检索完成后」场景，参照 Codex 的好做法（明确拒绝排序 + 客观分层而非排名次 + 取舍交用户），并避免「最相关/最重要/最该读/基石/天花板/绕不过去」等措辞。断网子项两宿主均因测试方法局限未可靠验证，待系统层断网（hosts/pfctl）或交互式真实断网重测。
