## 怎么跑（v3 当前判据，spec §14.8）

> **当前状态：已跑、达标（2026-07-24）。** v3 SKILL.md（commit bd76fce）落地后按本小节实测：5 个独立 runner（脚本 A-选×3 / A-弃×1 / C×1）清空上下文各扮宿主跑一遍、逐轮记录系统选项原话 + 落盘报告全文（本地 SDD 记录 `.superpowers/sdd/gate-run-*.md`，gitignored 不入库），独立审查员 rev-gate 逐轮 + 逐报告审五条判据，**零命中 = 达标**。结果见下方两张审查表 + 「结论记录」第 3 行。

1. 用 [`模拟用户回答脚本.md`](模拟用户回答脚本.md) 的 **脚本 A**（主案例方向）作固定输入，走 v3 的两条固定选择路径——**A-选**（遇选项就选其中一个）与 **A-弃**（遇某组选项全弃、改自填）；
2. **同一宿主、同一模型**，**清空上下文**独立开 3 个会话，各跑一遍——严格按脚本回答，skill 问到脚本没预设的分支时用同等模糊程度的回答延续（不临场变具体）；
3. **完整记录 3 次会话的逐轮系统给的选项原话**（不只是最终 RQ），并留存每次落盘的 HTML/md 报告；
4. 逐轮把系统给的选项对照下方「逐轮选项审查表」的五条判据前四条（① 只摆客观事实 / ② 无排序无打分 / ③ 带出口"以上都不是" / ④ 最终 RQ 用户拍板），命中即摘录原文、标注命中判据；
5. 逐份报告对照第 ⑤ 条（报告零结论），填「报告零结论审查表」；
6. 3 次会话逐轮 + 3 份报告**五条全过** → 达标；任意一次任意一轮 / 任意一份报告命中任一条 → 不达标，记入「结论记录」并降级 Phase 2。
7. **脚本 C**（阶段 3 反常识检测夹具）加跑 3 次，验证系统在阶段 3（纯追问、无选项）明说抬杠 / 唱反调对象仅限用户自己主张 / 不下"行不行"结论 / 判断权交回用户——阶段 3 无选项，不受"给选项"判据约束，逐轮命中"暗中引导 / 引入 AI 新方向 / 下'行不行'结论"任一即不达标。
8. （可选加严）用 **脚本 B**（法学对照方向）再跑，额外核查 skill 未把法学选题套进实证变量模板、且法学方向的选项同样只摆客观常见事实。

## 本次审查发现的新灰色地带（供下一轮修订参考）

1. **"复述用户已说词汇再追问偏好" vs "AI 凭空拼选项"**：第 2 次会话第 6 轮"这两件事——写东西、查资料——……更容易冒出疑问、更想深挖的是哪一件？"里的两个词是用户自己先说的，与 AI 凭空拼出"动手做 vs 评估检查"这类全新类别性质不同，从严未计入本次不合规轮次——但严格按红线 1"绝不夹带候选答案"的字面标准，把用户自己说过的两个并列项重新摆出来问"选哪个"，仍可能构成变相的二选一供给，只是风险等级低于凭空拼选项。**建议下一轮修订 SKILL.md 时明确区分这两种情形的合规边界**，而非笼统归为同一条规则。
2. **"设计方案二选一"边界**：多次会话中出现"是同一批人前后看，还是两批人分组看"这类问法——这不是候选 RQ 本身，是在暗示具体的**研究设计**（前后对照 vs 组间对照）。三次会话的 agent 自评都独立指出这类问法"逼近边界"，说明这是一个比"候选 RQ 二选一"更隐蔽、更容易被忽略的供给形式，值得在红线 1 里单独点名。
3. **"卡住时换角度追问"策略的结构性风险**：三次会话的违规轮次高度集中在"用户用固定延续语连续卡住、AI 尝试'换一个更小的问法'"这个环节——这不是随机分布的疏忽，是这个应对策略本身在结构上倾向于"我先想好几个具体选项，从中挑一个更小的问"。**下一轮修订应优先处理这个结构性诱因**，而非继续在红线措辞的字面覆盖度上打补丁。
