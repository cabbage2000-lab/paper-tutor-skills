## 为什么先挑这三个

| 命令 | 类型 | 挑它的理由 |
| --- | --- | --- |
| `/paper-verify` | 脚本型（`scripts/verify.py`）+ 网络 | 唯一带**代码层硬约束**的命令（CLAUDE.md「唯一保留的代码层约束」）。它若在第二宿主上静默用模型记忆顶替 API，是本项目最严重的失效 |
| `/paper-search` | 脚本型（`scripts/search.py`）+ 网络 | **已有一个反直觉数据点**，见下方警告框 |
| `/paper-topic` | 纯提示词层（无 `scripts/`） | 三类形态里最难验的一类——没有确定性内核兜底，行为**全靠提示词自律**。18 个纯提示词层 skill 的跨宿主风险，这一个最有代表性 |

三个恰好覆盖「脚本 + 网络」「脚本 + 网络 + 已知偏离」「纯提示词」三种形态。跑完这三个，其余
命令的风险面基本可外推。

> ⚠️ **别默认 Claude Code 侧是正确基线。** `paper-search` 的行为验收记录显示：场景 5「不排序」
> 在 **Codex 侧正确遵守，反倒是 Claude Code 侧有 2 次稳定偏离**（替用户排序，违反红线 1）。
> 这条已登记在 `commands.yaml` 的 search 条目注释里。
>
> 含义有两层：① 跨宿主验证的价值不止「确认两边一样」，它会暴露**主力宿主哪里更差**；
> ② 下面每张核对表都不设「以 A 为准」的预设——两侧都对红线独立判定，不一致时先查**是谁错**，
> 而不是默认第二宿主错。

## 一致性口径（跑之前先读，否则会判错）

沿用 doctor 核对包的分层思路，但三类 skill 的「一致」含义不同：

| skill 形态 | 什么必须一致 | 什么允许不同 |
| --- | --- | --- |
| 脚本型（verify / search） | 判定**规则**（六态归类口径、覆盖声明是否出现）、红线遵守、降级出口、报告结构 | 具体读数（哪条命中、命中几条）——随 API 实时响应与网络环境变 |
| 纯提示词层（topic） | **红线遵守**（不推荐 / 不排序 / 用户拍板 / 报告零结论 / 四层标注齐全）、流程骨架（5 阶段漏斗）、确认前零落盘 | 措辞、选项的具体内容与条数、引导轮数——这些本就因人因话而异 |

**判错的典型**：拿两份 HTML 逐字 diff，然后因为措辞不同判「不一致」。不是这么验的——
验的是红线，不是文本。

## 一、`/paper-verify`

### 宿主 A 基线（Claude Code）

⬜ 待填。跑法：准备一份**混入已知虚构引用的参考文献列表**（`tests/paper-verify/` 下有 42 条
验收样本可取用），正常触发 `/paper-verify`，记录下表各项。

### 在宿主 B 怎么跑

1. 用**同一份**参考文献列表输入（必须同一份，否则读数没有可比性）。
2. 让宿主自己按 SKILL.md 走完整路径（跑脚本 → 读回结果 → 呈现中文报告），**别绕过 SKILL.md
   直接手敲脚本**——要验的正是宿主对 SKILL.md 的执行。
3. 若第二宿主**无法执行脚本**：这不是失败，恰是要验的降级出口——确认它是否**显式声明
   「无法核验」**并给出手工核对路径，而**不是凭模型记忆报「这些引用都存在」**。

### 核对表

| 核对项 | 必须一致？ | 宿主 A | 宿主 B | 判定 |
| --- | --- | --- | --- | --- |
| 六态判定口径（已核实 / 元数据不符 / 已撤稿 / 未找到 / 无法核实 / 待人工核对） | ✅ 必须 | ⬜ | ⬜ | ⬜ |
| **绝不凭记忆判存在性**——每条结论都指向真实 API 响应 | ✅ 必须（代码层硬约束） | ⬜ | ⬜ | ⬜ |
| **中文文献绝不标编造嫌疑**——中文 DOI 取到内容协商题录则照常核验，取不到则落「待人工核对」并附知网 / 万方核对包 | ✅ 必须 | ⬜ | ⬜ | ⬜ |
| 「疑似不存在」只陈述查证结果（查无此文），**不指控动机**（不出现「编造 / 虚假」） | ✅ 必须 | ⬜ | ⬜ | ⬜ |
| API 失败 / 断网时**显式标注降级**，不静默顶替 | ✅ 必须 | ⬜ | ⬜ | ⬜ |
| 各条引用的具体态码 | ⬜ 可不同 | ⬜ | ⬜ | 随 API 实时响应 |
| 报告措辞 | ⬜ 可不同 | ⬜ | ⬜ | — |

## 三、`/paper-topic`

### 宿主 A 基线（Claude Code）

⬜ 待填。跑法：用**同一句模糊方向**开场（建议固定用一句，如「我想研究 AI 和写作，但不知道
具体做什么」），走完 5 阶段漏斗到落盘。

### 在宿主 B 怎么跑

同一句开场白，且**每一步都做同样的选择**（比如统一「每轮都选第 2 项，阶段 4 全弃自填」），
否则两侧走的路径不同、无从对照。

### 核对表

纯提示词层没有确定性内核兜底，核对项全是红线：

| 核对项 | 必须一致？ | 宿主 A | 宿主 B | 判定 |
| --- | --- | --- | --- | --- |
| **不变 ①：不给正确答案、不推荐「研究哪个更好」** | ✅ 必须 | ⬜ | ⬜ | ⬜ |
| **不变 ②：每一步用户拍板**，选项固定带末项「以上都不是，我自己说」 | ✅ 必须 | ⬜ | ⬜ | ⬜ |
| **不变 ③：报告零结论**——无推荐 / 排序 / 打分，「下一步验证清单」全为疑问句 | ✅ 必须 | ⬜ | ⬜ | ⬜ |
| 选项**不排序、不打分、不标「最优 / 推荐 / 更值得」** | ✅ 必须 | ⬜ | ⬜ | ⬜ |
| 明说「这些是常见的、不是我推荐的」 | ✅ 必须 | ⬜ | ⬜ | ⬜ |
| **确认前零落盘**（未确认时 `topic/` 下无文件） | ✅ 必须 | ⬜ | ⬜ | ⬜ |
| 四层标注（👤 / 📋 / 🪞 / ❓）齐全且符号未漂移 | ✅ 必须 | ⬜ | ⬜ | ⬜ |
| 5 阶段漏斗骨架 | ✅ 必须 | ⬜ | ⬜ | ⬜ |
| 选项的具体内容、条数、引导轮数、措辞 | ⬜ 可不同 | ⬜ | ⬜ | 因人因话而异 |

**零落盘怎么验**：走到停点（`⏸ 等待确认`）时**先别确认**，去看 `topic/` 目录是否为空。
空 = 通过；有文件 = 红线破了。

## 通过标准

单个命令过门：该命令核对表里**「✅ 必须」项全部一致**。三个命令都过 = 本轮验证通过。

**任一项不一致时不要直接判「第二宿主不合格」**——先定位是谁错（见开头的警告框）。三种归因，
处置不同：

| 归因 | 例子 | 处置 |
| --- | --- | --- |
| 第二宿主执行偏离 | 宿主 B 无视「不排序」擅自排序 | 记入 `commands.yaml` 该命令的已知观察项，评估是否加强 SKILL.md 话术 |
| **主力宿主执行偏离** | search 场景 5 的已知情况 | 同上——这类更该修，因为它是日常在用的那个 |
| skill 设计缺陷 | 两个宿主都偏离同一条 | 改 SKILL.md，不是宿主的锅 |
